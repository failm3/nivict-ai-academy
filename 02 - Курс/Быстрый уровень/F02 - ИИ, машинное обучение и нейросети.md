# F02. ИИ, машинное обучение и нейросети

> **Статус:** завершён на вводном уровне. Пользователь самостоятельно объяснил разницу ручных правил и ML, классификации и генерации, а также отличил тип языковой модели от задачи. Путаница во вложенности AI/ML/DL была разобрана с аналогией автомобиля. Практическая разработка моделей не проверялась.

## Основная идея: три вложенные области

- **AI (Artificial Intelligence / искусственный интеллект)** — широкая область создания систем для интеллектуальных задач: поиска решений, планирования, распознавания и др. Может включать методы **без машинного обучения**.
- **ML (Machine Learning / машинное обучение)** — часть AI: алгоритм настраивает модель на основе данных. ML **не обязан** использовать нейросети: например, обученное дерево решений.
- **DL (Deep Learning / глубокое обучение)** — часть ML, основанная на глубоких (многослойных) нейросетях.

**DL ⊂ ML ⊂ AI.** Это не три разговаривающих друг с другом компонента, а вложенная классификация подходов. Аналогия: электромобиль одновременно и автомобиль, и транспортное средство.

## Анализ против обучения

- Программа может интеллектуально анализировать миллионы шахматных позиций и выбирать сильный ход, даже если не меняет свои параметры на основе сыгранных партий.
- **Анализ** решает текущую задачу; **обучение** использует данные для настройки модели, влияющей на будущие решения.
- Наличие базы данных с сыгранными партиями само по себе **не обучает** программу. База хранит сведения, а алгоритм обучения должен их обработать и настроить модель. При этом обучающие данные не обязаны находиться в отдельной базе данных.
- Нейросеть в обычном режиме использования тоже не меняет веса автоматически после каждой ошибки.

## Ручные правила и ML

**Обычная программа:** программист явно задаёт, например, «если письмо содержит фразу X, отметить как спам».  
**ML-модель:** алгоритм получает размеченные письма «спам/не спам» и настраивает параметры модели по данным. Она может распознать ранее не встречавшиеся формулировки, но только если хорошо обобщает изученные закономерности. Больше примеров само по себе не гарантирует качество.

**Дерево решений** может быть моделью машинного обучения: алгоритм автоматически выбирает полезные признаки и пороги из данных, без каких-либо искусственных нейронов. Если правила дерева полностью прописаны вручную — это ещё не ML.

## Классификация и генерация

- **Классификационная задача:** определить класс входных данных, например «дизайнер / разработчик / маркетолог» по резюме.
- **Генеративная задача:** создать содержание, например написать текст резюме по описанию вакансии.
- Одна **генеративная языковая модель** может решать обе задачи. Когда ChatGPT отвечает только «дизайнер», он может выполнять задачу классификации *через генерацию текстового ответа*; архитектура модели от этого не становится иной.
- Выданное языковой моделью объяснение решения не обязано достоверно описывать её внутреннюю процедуру принятия решения.

## Важные различия

| Понятие | Не путать с |
|---|---|
| Робот | Физическая система; наличие робота не означает наличие AI или ML |
| Искусственный интеллект | Не обязательно нейросеть и не обязательно непрерывно обучается |
| Машинное обучение | Не обязательно нейросеть |
| Глубокое обучение | Всегда подмножество ML, а ML — подмножество AI |
| Наличие данных или хранилища | Не равно процессу обучения |
| Тип модели | Не равен типу задачи, которую ей поручили |

## Что ученик объяснил сам

- Обучаемая спам-система может быть устойчивее к изменению формулировок, если её учебные примеры разнообразны.
- Алгоритм на основе данных, а не разработчик вручную, определяет структуру обученного дерева решений.
- Классификация присваивает одну из категорий; генерация создаёт содержание.
- В задаче «определи профессию и объясни» присутствуют классификационная цель и генерация ответа.
- Тип генеративной модели не меняется от того, что её используют только для выдачи одного названия класса.
- Замечено, что проверочный вопрос с прямо указанным в условии типом модели слишком подсказочный: последующие вопросы должны быть содержательными, а не повторять ответ из условия.

## Что требовало исправления

- «AI — это всегда обучающаяся нейросеть» → нет, ИИ шире.
- «Без новой базы данных нет обучения» → наличие/отсутствие БД не определяет наличие обучающего алгоритма.
- «DL может работать отдельно от ML» → нет, DL определён как часть ML, AI — более широкая область.
- «Алгоритм сам перечисляет все варианты вручную» → различать явно написанные правила и правила, полученные при обучении.

## Как объяснить сотруднику

«ИИ — широкая область. Машинное обучение — её часть, где модели настраивают по данным. Глубокое обучение — часть ML, использующая многослойные нейросети. Система может быть ИИ без самообучения; дерево решений может быть ML без нейросети; генеративная языковая модель может выполнять классификацию, не меняя своего типа».
