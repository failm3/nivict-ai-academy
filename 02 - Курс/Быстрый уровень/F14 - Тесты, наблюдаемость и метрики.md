# F14. Тесты, наблюдаемость и метрики

> **Статус:** начат после F13. Понимание F14 пока не проверено.

**Опора:** [[02 - Курс/Быстрый уровень/F13 - Требования, результат и доказательства|предыдущий урок]]  
**Главная мысль:** Качество агента оценивается на тестовых задачах и по реальным действиям; журналы и метрики позволяют находить причины ошибок.

## Что разберём последовательно
1. Тестовые сценарии и ожидаемый результат.
2. Лог, trace и последовательность вызовов.
3. Качество, задержка, стоимость, доля успеха.
4. Почему один удачный пример ещё не доказательство надёжности.

## Один конкретный пример
Из десяти проверочных заявок агент корректно классифицировал восемь; trace показывает два ошибочных вызова инструмента.

## Зачем это будущему инженеру
Разбираться в логах, дефектах и метриках, не полагаясь на объяснения модели.

## Зачем это для платформы создания агентов
Проводить приёмочные проверки для каждого нового агента перед публикацией.

## Короткая проверка понимания
Объяснить, почему один демонстрационный запуск не позволяет утверждать «агент надёжный».

## Типичная ошибка
Считать тексты рассуждений модели достоверным журналом действий.
