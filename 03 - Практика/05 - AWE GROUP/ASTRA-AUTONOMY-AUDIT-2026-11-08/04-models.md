# D. Модели, маршруты и стоимость принятого результата

## Что выбрать

**Стартовый набор — один локальный worker на Mac, один условно доступный облачный маршрут и программный broker в AWE.** Локальный Qwen обрабатывает вакансии и частные обстоятельства владельца. Для сложного плана, frontend/backend и дизайна начать сравнение с GPT-6.1 Sol только там, где разрешены регион, данные и оплачиваемый аккаунт. Для инфраструктуры в РФ практический кандидат облачного пилота — Yandex AI Studio. Если все внешние маршруты закрыты, первый отклик всё ещё возможен через локальную модель и утверждённые шаблоны. Качество русского текста — предмет экзамена на миссии.

Размеры на диске даны для конкретных сборок. Peak RAM = веса + KV/состояние модели + prefill/vision buffers + runtime + ОС. Стартовый инженерный лимит 16 GiB на inference, запас порядка 8 GB всей машине, без второго server и обучения одновременно. Измерить память, swap, TTFT и decode tok/s на самом Mac. При 273 GB/s у M4 Pro один проход 5,2 GB весов за токен даёт идеализированный ориентир ~52 токена/с для dense decode batch=1. Это оценка порядка величины по пропускной способности. Реальные prefill, KV, quantization, температура и длина контекста изменят результат. Предлагаемая цель пилота ≥15 decode токенов/с и p95 TTFT ≤5 с на типичном коротком запросе. Измеренной скорости владельца пока нет. [Apple M4 Pro](https://www.apple.com/macbook-pro/compare/?modelList=MacBook-Pro-14-M4%2CMacBook-Pro-14-M4-Pro)

Ollama даёт локальный schema-constrained JSON. Синтаксическая валидность не устанавливает правильность `vacancy_id`, гражданства, денег и действий. Для инструментов отдельно проверять chat template, валидность аргументов, невозможность вызвать незаявленный инструмент и лимит шагов. Для MLX-модели независимо проверить поддержку нужного формата сервером, либо использовать текстовый вывод + schema validation и одну локальную починку. MLX-LM 0.32.2 опубликован 16 октября. Для первого пилота достаточно одного runtime, второй нужен при A/B или LoRA. ### Алгоритм выбора и смета

1. Если операцию точно выполняют SQL/JS/API, её цена LLM равна нулю. Фильтрация, dedupe, расписание, контроль бюджета, подтверждение отправки и чтение статуса выполняются кодом.
2. Фильтр policy удаляет запрещённые data classes, регионы, неизвестные retention, неподтверждённые tool/schema/vision, старые quotes и недоступные endpoints. Если список пуст — продолжить другие задачи, поставить эту в WAIT.
3. По `task_class + language + length` выбирать минимальную прогнозную стоимость успешного результата среди прошедших порог качества и срока. Для маршрута считать `(инференс + проверка + ожидаемые исправления + цена ожидания) / P(принятия)` на одинаковом holdout. Хранить реальные числитель/знаменатель по каждой попытке и целой миссии. При малом числе наблюдений использовать консервативную нижнюю границу success, показывать размер выборки.
4. До вызова резервировать максимум ввода, выдачи с billed reasoning, tool fees и валютный запас, отключить автоматические retries SDK. Привязать к quote expiry, точным тарифным ступеням и revision. После ответа сверить usage/receipt. Кэш учитывать по подтверждённому cache read. Перед новым маршрутом создать отдельный резерв. При неизвестном биллинге держать прежний резерв, до решения сверки ограничить новые расходы остатком мандата. Для внешнего отклика никакого модельного failover-send.
5. Обновлять health по 401/403/429/5xx отдельно. Не менять провайдера для запрещённых данных. Допустимая цепочка: локально → при низкой оценке разрешённый Sol/региональный backend → независимая QA → одна адресная коррекция. Вызов Astra только при наличии высокого ценового/технического выигрыша.

Пример без кэша и инструментальных сборов: 20k input + 2k output стоят **$0,003** на Luna, **$0,06** на Sol/Sonnet, **$0,30** на Astra или **2,40 ₽** на Alice Flash. Один Sol draft + один Sol QA с такими же объёмами = $0,12 за попытку. При условных 80% принятых приблизительно $0,15 на принятый пакет. Для 100 таких пакетов около $15 inference, без налогов, подписок, площадок и времени человека. Это сценарий, не обещание цены отклика. До пилота не известны реальный mix задач, доля отказов, post-send reconciliation и потребление токенов. Метрики владельца — расход на принятый пакет, на подтверждённый первичный отклик и позднее на приглашение.

### Измерение качества и LoRA

Проект пилота: 40 разрешённых/синтетических RU/EN пар «вакансия–профиль», включая дубликаты, удалённую вакансию, запрещённое поле и prompt injection. Дополнительно 10 JSON/tool задач, 5 задач изменения кода и 5 визуальных ошибок. Равные input, output cap и QA rubric, изолированные трассы. Регистрировать слепое парное предпочтение двух резюме/писем, факты с указателями на профиль, macro-F1 для извлечения, recall релевантных ролей, ошибки schema/tool, p50/p95 latency, peak memory и фактическую стоимость. Первый допуск в автоматическое ранжирование: ≥95% корректных обязательных полей, ни одного вымышленного достижения или запрещённого эффекта в наборе, неоднозначные случаи маршрутизируются на review. Карточка с 40 примерами не обещает такой процент в эксплуатации.

Команды для подготовленного Mac **после локального provisioning**. `model.gguf` — уже проверенный скачанный файл, сохранить его SHA, версию backend и длину context. Использовать Metal сборку. Второй тест на реальном job JSON нужен отдельно от чистого декодирования.

```sh
shasum -a 256 model.gguf
llama-bench -m model.gguf -p 512,2048 -n 128 -r 5 -o json
memory_pressure -Q
```

LoRA меняет малую матрицу адаптера. QLoRA обучает её поверх квантованной замороженной основы. На 24 GB начать эксперимент с 4B Q4, batch=1, sequence 512–1024, ограниченным числом слоёв, раздельными train/valid/test по компаниям и времени. Возможность 8B зависит от фактического peak и длины, full fine-tune не планировать. У MLX-LM есть локальные LoRA/QLoRA; CUDA/bitsandbytes не закладывать как обязательное для Mac. Хранить adapter отдельно от base SHA, rollback — отвязать adapter. Сначала исправлять форму задания, retrieval и tools. Обучение оправдано при повторяющихся измеренных ошибках RU extraction/style и достаточном числе проверенных примеров с правом обучения. Ни вакансии HH, ни персональные письма, ни секреты не попадают в обучающий корпус по умолчанию. [MLX-LM LoRA](https://github.com/ml-explore/mlx-lm/blob/main/mlx_lm/LORA.md) · [llama-bench](https://github.com/ggml-org/llama.cpp/blob/master/tools/llama-bench/README.md)
