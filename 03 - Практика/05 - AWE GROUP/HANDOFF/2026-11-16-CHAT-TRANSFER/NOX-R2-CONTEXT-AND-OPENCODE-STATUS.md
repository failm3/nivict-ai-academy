## 3. Архитектура Nox и её отличие от OpenCode

Owner → Prompt Master (спецификация / approval) → Head (план, роли, capabilities) → Mission Manager (делегирование, параллельность, retries/replanning, checkpoints) → Specialists (file/shell/web/browser/tools) → независимый QA/verification → результат + memory/experience. Отдельные host-owned permissions, модели, бюджеты, admission, qualification. Mastra, libSQL, Playwright, MCP и другие библиотеки являются реализационными компонентами. Nox должен автономно выбирать инструменты и приобретать недостающие capability через проверку, а не просто смотреть каталог.

Историческое состояние до R2: полноценная мультиагентность и инструменты были ограничены; постепенно реализованы Head/PromptMaster/MissionManager/QA, Recursion, resource controls, QA artefact binding, model ledger, capability discovery, UCL advisory. Сведения о конкретных продакшн-возможностях всегда сверять с текущей ревизией.
