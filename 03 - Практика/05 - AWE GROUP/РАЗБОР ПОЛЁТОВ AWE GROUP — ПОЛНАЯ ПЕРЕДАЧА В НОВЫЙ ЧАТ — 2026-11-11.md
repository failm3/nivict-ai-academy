# AWE GROUP — ПОЛНАЯ ПЕРЕДАЧА ДЛЯ РАЗБОРА ПОЛЁТОВ (11.11.2026)

> **ГЛАВНАЯ ИНСТРУКЦИЯ НОВОМУ ЧАТУ:** владелец хочет **обсудить, почему собственная AWE GROUP не стала рабочим аналогом Manus**, при том что прямо сейчас независимые готовые платформы **Manus и Kortix** запущены на CAREER-01. **Не возобновлять разработку, не запускать процессы, не переписывать архитектуру и не переключаться на управление CAREER-01**, пока владелец не попросит. Нужно вместе разобрать фактические технические и управленческие ошибки, исходные решения, их причины и разумное дальнейшее использование уже созданной AWE. **Не путать гипотезы с доказанными причинами.**

## 1. Исходная цель владельца — принципиально не терять

AWE GROUP — **универсальная, автономная, расширяемая, мультиагентная система под руководством владельца**, а не только бот по поиску вакансий или интерфейс поверх LLM. Желаемая цепочка:

**Большая миссия → Prompt Master / формализация → Head Agent → декомпозиция → динамическое создание специализированных подагентов → выбор подходящих LLM и рабочих инструментов → параллельное реальное выполнение → независимый QA и исправление → память / сохранение / восстановление → продукт.**

Если инструмента/возможности нет, агент должен **искать готовую интеграцию, законно подключать и тестировать её, затем применять к текущей миссии**, а не бесконечно проектировать инструменты; самописный код только при доказанной необходимости. В перспективе — собственные технологии, обучение/дообучение локальных моделей и собственная LLM, но это **следующие этапы, не условие запуска первых задач**.

Владелец хотел **«копию Manus» по уровню пользовательской автономности и полезности, но под собственным контролем**. Он не требовал сначала писать всё с нуля. Разработка длится долго, по словам владельца затрачены сотни часов; это **его оценка временных затрат**, а не автоматически подтверждённый тайм-трекинг.

- В `awe/hermes_runtime/hermes-source-lock.json` фиксировалась версия и исходники-кандидаты Hermes; lock-файл не доказывает, что Hermes реально установлен как подключённый живой исполнитель.

## 4. 11 ноября — сравнение с готовыми продуктами: Manus и Kortix (свежая пользовательская информация)

### Почему выбран готовый софт
Владелец спросил, почему Manus выполняет задачи, а собственная AWE застряла; не хочет обязательной подписки Manus. Нужен готовый открытый агентный сервис, работающий **через собственные платные LLM API Router.Cheap**. Требование **не запускать локальную платформу в WSL как постоянный сервер**: пользователь хочет облачную, доступную через браузер систему. Рассматривались Eigent, OpenManus, Kortix. Текущим готовым кандидатом стал **Kortix CompanyOS** (бывший Suna), а Manus запущен для независимого сравнения. Это выбор для пилота, не доказанное решение архитектурной проблемы AWE.

### Kortix CLI / Windows / WSL
- PowerShell 5.1 `curl -fsSL ... | bash` не сработал: псевдоним `curl` указывал на `Invoke-WebRequest`; `kortix` отсутствовал до установки.
- Через `wsl -d Ubuntu` установка `curl -fsSL https://kortix.com/install | bash` прошла успешно: **Kortix CLI v0.15.6**, путь `/home/nox/.kortix/kortix`, symlink в `~/.local/bin`, SHA-256 binary проверен; cosign-подпись отдельно не проверялась.
- Команды `kortix self-host init/start/status` дошли до запроса `domain/tunnel`, подтверждённого запуска облачного собственного инстанса нет. Установка **CLI не означает self-host платформы**.

### VPS / бюджет / урок по стоимости
- Рассмотрели Hostinger и российский Timeweb Cloud; пользователь требует русскоязычный сервис с оплатой российской картой и НЕ хочет зависеть от домашнего ПК.

## 5. Почему своя AWE не достигла Manus-подобной полезности — гипотезы для предстоящего разбора, НЕ готовый вердикт

Технические гипотезы:
1. **Преждевременный control-plane / сложность до product-market proof:** спроектировали полномасштабное управление, гейты и реестры раньше живой вертикали `LLM → tool → action → QA`.
2. **Mock/evidence substitution:** PASS и следы состояния принимались за практический прогресс; E0-успех неверно экстраполировался на E1.
3. **Tool discovery ≠ execution:** 4504 кандидата, но runtime dispatch запрещён/не реализован; проблемы capability acquisition, browser access, security policies и разрешений.
4. **Нехватка рабочей изолированной среды:** реальная браузерная/файловая/кодовая песочница, интерактивные сайты, screenshot/visual QA не доведены до доказанного исполнения.
5. **Head, Prompt Master и subagent lifecycle:** отсутствовала либо была ограничена самостоятельная динамическая организация команды; fixed DAG не равен автономной командной работе.
6. **Модельная политика / стоимость / retry:** ограничения доступности моделей, локальная 4B, неверные лимиты и повторы ошибки repair-loop; нужна фактическая трассировка, чтобы подтвердить вклад каждого.
7. **QA без соответствия пользовательскому продукту:** проверяли HTTP/DOM, но не качество профессионального дизайна и необходимость реальных сайтов; ночь дала визуально отвергнутый output.
8. **Менеджмент приоритетов и ТЗ:** задачи расходились на технические направления, частные успехи теряли связь с общей миссией; нужно восстановить, кто, когда и почему санкционировал такое расхождение.
