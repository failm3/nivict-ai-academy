# AWE GROUP — личный срез для владельца

**Состояние доказательств:** 10 ноября 2026, до 20:25 МСК.  
**Не является live-мониторингом**: после 20:25 в этом отчёте нет нового прямого readback из WSL.  
**Основание:** оригинальный E1-LIVE /goal (сохранён в GitHub), выводы владельца из AUDIT/CHECKPOINT на 18:44 и 19:50, Telegram-сообщения OpenCode 20:11–20:25.

## Главное
Мы ещё не запустили самостоятельную AWE GROUP. **OpenCode — инженерный исполнитель — продолжает строить её ядро.** Изолированные тесты показывают значимый прогресс по защите от повторов, сохранению состояния, исполнению и независимому техническому QA, но не доказали реальную автономность.

## Что было задумано
Одна большая задача OpenCode: сначала сохранение и аудит существующей E0/E1; затем настоящий сквозной сценарий с реальной LLM, инструментом, независимым QA и памятью; затем динамические агенты, параллельность, маршрутизация моделей и инструментов, саморазвитие; реальные испытания; разрешённые направления CAREER-01; продолжение с checkpoint. **Одна тестовая миссия — только первый обязательный рубеж, не финал.**

## Что уже создано и проверено в ограниченных тестах
- Изолированная рабочая папка `/home/nox/awe-e1-launch-20261110` и архив исходной; оригинальная E1 сохранена по аудиту.
- Native bridge к уже существующему координатору: task leases/fences, контроль попыток, резервирование и отсутствие слепых повторов.
- Durable file journal для записи/редактирования; agent cursor, atomic lifecycle/agent start/task admission, восстановление после остановки и потери подтверждения.
- Независимый reviewer-процесс, sandbox на основе bubblewrap, read-only snapshots, ограниченное RPC-взаимодействие, durable QA outcomes `PASS/FAIL/BLOCKED` и negative disposition.
- Native cancellation испытан; в неизвестном исходе `SENDING/UNKNOWN` сохраняет `HOLD`, а известные допускаемые исходы освобождают ресурсы.
- Последнее сообщение OpenCode: `268/268 PASS` в расширенном наборе, `442/442 PASS` базовой регрессии, приватный архив 258 файлов. Это **самоотчёт исполнителя**; результаты наборов перекрываются, их нельзя складывать.

## Важная обнаруженная проблема
В scripted holdout-контролях **три семантически неверных PASS прошли RPC/hash gate**, но дополнительный evaluator нашёл ошибки. Значит, техническая целостность и изоляция QA есть, однако смысловая достоверность решения не гарантирована. Нужно сделать так, чтобы ошибочный PASS не принимался без полноценного независимого quality gate. Это существенная причина не принимать систему как готовую.

## Что НЕ сделано / НЕ подтверждено
- На последнем checkpoint: `first_checkpoint_met=false`, `real_llm_vertical_slice=NOT_RUN`, `independent_agent_qa=NOT_RUN`; реальная сквозная LLM-миссия E1 не состоялась.
- Реальный оплачиваемый LLM-маршрут и достоверный контроль расходов не допущены; E1 `new_paid_generations_initiated_by_tools=0` — **не** про стоимость инженерной сессии OpenCode.
- Динамическое формирование команд, безопасная параллельность, самостоятельный выбор LLM и инструментов, приобретение недостающих возможностей и выполнение CAREER-01 пока не доказаны.
- Автоматическое terminal lifecycle было в разработке в 20:25 (host-only terminal receipt); native cancel сам по себе ещё не означает, что автоматическая связка подключена.
- По прежнему аудиту, изменения в изолированном worktree ещё не были зафиксированы обычным Git-коммитом из-за отсутствующей Git author identity; локальные файлы нельзя путать с GitHub push.
- GitHub CHAT-LOGS создаётся через вызовы ассистента, **не** подключён фоновый auto-collector всех сообщений.

## Что мешает запуску
Главный явный запрет платного E1 теста — три неуточнённых вопроса о Router.Cheap:
1. Локальный путь **разрешённого ключа** (сам секрет никуда не отправлять).
2. Точный **model ID** единственной разрешённой модели.
3. Лимит **$20** — это общее разрешение на расходы по ключу или дополнительные $20? Аудит нашёл другие фактические hard limits, которые нельзя считать разрешением.
Также требуется завершить negative QA/terminal lifecycle и подтвердить безопасность production-подключений. Изолированная PG 5545 — тестовая.

## Как идёт работа
По предоставленной хронологии видны последовательные результаты: на 18:44 task admission, к 19:50 изолированный QA, к 20:25 sandbox holdout и контракт безопасного завершения. Это реальные признаки продвижения. Но темп исполнения конечной миссии нельзя оценить только по PASS. Ошибки провайдера `ECONNRESET` в 20:11 и 20:24 прерывали связь; после них в 20:25 были сообщения о новых действиях. Нельзя автоматически считать сессию остановленной или исправной сейчас; её текущее состояние требует свежего API readback. Не применять `/abort` вслепую.

## Реальная последовательность следующих шагов
1. Завершить terminal lifecycle и зафиксировать исходы отрицательного QA без потери/повторов.
2. Привязать проверяемый реальный QA gate к итоговой приёмке.
3. Уточнить разрешённый Router.Cheap ключ, model ID и бюджет; затем безопасный D09/ledger/PG runtime.
4. Запустить **одну настоящую сквозную миссию** с LLM, инструментом, памятью и независимым QA — первый checkpoint.
5. После её прохождения реализовать динамические команды, безопасную параллельность, маршрутизацию, саморазвитие; проверить на реальных заданиях.
6. Начать разрешённые блоки CAREER-01; не отправлять заявки/письма третьим лицам без отдельного разрешения.

## Вывод
**Фундамент заметно продвинулся, но главная функция — самостоятельное выполнение задач через реальных агентов — пока не доказана.** Невозможно честно назвать процент готовности. Мы преимущественно завершали надёжность и QA, а не финальные прикладные возможности. Существующий `/goal` нельзя заменять новым упрощённым заданием.
