## Инженерная оценка

- Подтверждено: чистый отдельный проект, работающая OpenCode TUI, прочитанное ТЗ, попытка рационально выбрать сторонние библиотеки.
- Не подтверждено: написанный и запущенный исходный код AWE, реальное дерево подагентов, работа MCP/браузера, independent QA, persistent recovery, фактическая модель/платежи, Git commits.
- Решение переиспользовать зрелые SDK лучше, чем писать с нуля новый framework. Но до первого исполняемого вертикального среза нет подтверждённого результата.
- **Риск:** `in-process` queue теряет незавершённые задания после аварии, если состояние не сохраняется отдельно.
- **Риск:** auto-approval и отдельная папка не равны OS-sandbox; shell всё ещё обладает правами WSL пользователя.
- **Риск:** бесконечные проверки версий библиотек вместо реализации. На текущем снимке недостаточно данных, чтобы утверждать, что агент застрял.
- **Вердикт:** исполнитель приступил к работе, но успешная реализация AWE пока не доказана.

## Для полного аудита

OpenCode официально предоставляет `session list --format json`, `session export <ID> --sanitize`, `stats` и служебные logs:
- https://opencode.ai/docs/cli/commands/
- https://opencode.ai/docs/troubleshooting

Подготовлен read-only shell script `awe_opencode_audit_capture.sh` для запуска владельцем в новом clean-room WSL. Он выгружает доступные сессии, индекс tool calls, статистику, список Git-изменений, очищенные копии новых исходников, частично редактированные служебные логи в ZIP. Не запускает LLM-запросы, не читает прежние проекты, не останавливает текущий процесс. Любое автоматически замаскированное содержимое всё равно нужно проверить до внешней загрузки, если в нём могли оказаться секреты.

**Окончательная оценка возможна только после получения ZIP из реальной текущей сессии.**
