**Вы правы: оценку 240–480 часов нельзя использовать как оценку получения первой работающей AWE из готовой Agent Zero.** В ней я преждевременно объединил первоначальную настройку, интеграции и корпоративное развитие. Это завысило стартовый объём и создало неверное впечатление, что сначала нужно строить собственные подсистемы.

Исправленный подход: **запустить готовую Agent Zero, настроить роли, модели и инструменты, проверить полноценную миссию — и только затем устранять фактически обнаруженные ограничения.** Использование ИИ меняет способ выполнения работы, но я не буду переводить человеческие часы в агентное время произвольным коэффициентом.

## 1. Что можно получить без нового программного кода

Точечная проверка документации подтвердила больше возможностей конфигурации, чем было отражено в предыдущей оценке.

Agent Zero уже позволяет создавать профили с инструкциями, model preset и разрешениями Tools/MCP/Skills. Preset включает main, utility, embedding и опциональную vision-модель; настройки могут применяться к проекту и профилю. Профили доступны для делегирования. [Профили](https://github.com/agent0ai/agent-zero/blob/main/docs/guides/agent-profiles.md), [Model Presets](https://github.com/agent0ai/agent-zero/blob/main/docs/guides/model-presets.md).

| Часть AWE | Начальная реализация без нового кода |
|---|---|
| Prompt Master | Профиль или инструкции для уточнения миссии и критериев результата |
| Head Agent | Основной агент с правилами декомпозиции и делегирования |
| Специалисты | Профили Researcher, Developer, Reviewer и другие |
| Несколько моделей | Presets, назначенные профилям и проектам |
| Первичная политика выбора моделей | Назначение модели роли; выбор исполнителя руководителем |
| Локальное выполнение | Штатные браузер, терминал и файловые инструменты |
| MCP | Настройка готовых серверов и разрешений |
| Skills | Совместимые готовые процедуры и инструкции |
| Рабочие проекты | Штатные Projects |
| Повторяемые задания | Штатные Tasks |
| Память | Штатная память проекта и агента |
| Сохранение и резервирование | Штатные файлы, история и Backup/Restore |
| Проверка результата | Отдельный Reviewer с отдельным контекстом и проверками |
| Исправления | Инструкции на возврат замечаний исполнителю и ограничение попыток |
| Интерфейс | Существующий Web UI и Windows Launcher |

Projects, Tasks, браузер, память и Backup/Restore документированы в готовом приложении. [Руководство Agent Zero](https://github.com/agent0ai/agent-zero/blob/main/docs/guides/usage.md).

**Здесь «без кода» не означает «без работы».** Потребуются настройка, подготовка инструкций, credentials, проверка совместимости и испытания. Но это не разработка нового backend или UI.

Также готовые Skills не следует считать универсальными исполняемыми модулями: некоторые содержат только инструкции, другие предполагают отдельные зависимости. Совместимость проверяется до подключения.

### Чего конфигурация сама по себе не гарантирует

Назначение разных моделей профилям не равно автоматическому оптимизатору цены и качества. Reviewer не равен технически непробиваемому шлюзу приёмки. Инструкция «не превышать бюджет» не является жёстким денежным лимитом.

**Для первой версии эти ограничения допустимы, если они явно обозначены и миссии безопасны.** Они не мешают получить настоящую работающую систему.

## 2. Что переиспользовать из других проектов

Нужно различать готовую функцию внутри продукта и готовый интерфейс её подключения к Agent Zero.

| Проект | Уже существующая польза | Как использовать без создания аналога |
|---|---|---|
| OpenHands | Coding-агент, рабочие среды, SDK/Agent Server, события, сохранение бесед, reviewer-процессы | Делегировать ограниченные coding-задания через существующий интерфейс |
| CAMEL | Агенты, browser/interpreter toolkits, Workforce, экспорт агента в MCP | Подключить отдельного специалиста или инструмент; не добавлять второй главный Workforce |
| Eigent | Готовый desktop UI и координация workers | Рассматривать как альтернативную основную платформу, а не обязательный модуль Agent Zero |
| Microsoft Agent Framework | Workflow, checkpoints, tools, согласования | Использовать только для конкретного пробела, если он обнаружится |
| LangGraph | Графы выполнения, persistent checkpoints, interrupts | Не нужен для старта; возможен для отдельного сложного процесса |
| OpenManus | Инструменты выполнения и stdio MCP-сервер инструментов | Подключать только при преимуществе перед уже имеющимися инструментами |
| Kortix | Функционально близкое приложение | Не включать в старт: ранее выявлены ограничения локального runtime и лицензии |

У OpenHands документирован Agent Server; у CAMEL — экспорт агента в MCP. [OpenHands Agent Server](https://docs.openhands.dev/sdk/guides/agent-server/overview), [CAMEL MCP export](https://docs.camel-ai.org/mcp/export_camel_agent_as_mcp_server.md).

**Важная поправка:** я не могу обещать, что OpenHands подключится к Agent Zero исключительно одним полем настройки. Если готового совместимого коннектора нет, потребуется небольшой адаптер к существующему API. Это интеграционный код, а не создание собственного OpenHands.

Для первой AWE сторонний исполнитель вообще не обязателен: сначала нужно проверить, справляются ли штатные инструменты Agent Zero.

## 3. Какой код действительно необходим

**Для первой версии обязательных новых программных подсистем сейчас не выявлено.**

Дальнейшая разработка оправдана только при двух условиях: требуемое поведение не получается штатными средствами и нет подходящего готового компонента.

Потенциальные кандидаты:

- Адаптер Agent Zero ↔ внешний coding-исполнитель.
- Сквозной бюджетный контроль, если требуется общий лимит всех запросов.
- Технический запрет исполнителю принимать собственный результат.
- Восстановление миссии с учётом неизвестных внешних эффектов.
- Специфический корпоративный реестр задач и зависимостей.
- Собственный дистрибутив AWE, если Launcher перестанет удовлетворять требованиям.

Даже здесь **нельзя сейчас утверждать, что всё необходимо писать самостоятельно**. Часть функций может закрываться готовыми средствами провайдера, контейнерной инфраструктурой или существующими библиотеками.

## 4. Исправление оценки интерфейса, QA и памяти

### Интерфейс

Для старта:

**Новый UI: 0 часов разработки.**

Остаются запуск Launcher, настройка backend и проверка доступа к существующему интерфейсу. Время этих операций относится к развёртыванию, а не к разработке интерфейса.

Ранее указанные 24–48 часов следует убрать из первой версии. Они могли относиться к дополнительным панелям или собственному дистрибутиву, но таких требований для старта сейчас нет. [A0 Launcher](https://github.com/agent0ai/a0-launcher/releases/tag/v1.9).

### QA, память и задачи

Сначала используем:

- Reviewer-профиль и фактические проверки результата;
- штатную память и Backup/Restore;
- Projects и Tasks.

Не создаём заранее собственную память, PostgreSQL-диспетчер или QA-сервис.

**Первичная независимая проверка — отдельный агент с отдельным контекстом, который проверяет артефакт.** Корпоративная независимость — отдельная, более строгая задача: полномочия, неизменяемые критерии и блокирующая приёмка. Вторую не нужно делать условием существования первой.

## 5. Три сценария

Все интервалы ниже — **предварительные окна планирования, а не измеренная скорость или обещание срока**. Они предполагают доступ к выбранному компьютеру, исправные зависимости и предоставленные credentials.

«Время агента» означает длительность работы ИИ-исполнителя с инструментами, включая проверки. Человеческое участие указано отдельно и **не складывается механически** с этим временем.

### Сценарий A — минимум разработки

**Готовая Agent Zero + конфигурация.**

Переиспользуется весь runtime, UI, Launcher, проекты, память, делегирование и инструменты. Настраиваются роли, несколько моделей и один-два необходимых MCP-подключения.

**Новый программный код: 0.** Инструкции, presets и конфигурация не считаются новым программным backend.

Критерий готовности: одна миссия проходит полный цикл — уточнение, делегирование, реальные действия, артефакт, отдельная проверка и сохранение результата. В журнале видно использование минимум двух LLM-моделей.

| Измерение | Предварительный ориентир |
|---|---|
| Работа агента | 2–6 часов при беспроблемном развёртывании |
| Календарное окно | 4–12 часов; при несовместимости — дольше |
| Участие человека | 0,5–2 часа: доступ, ключи, подтверждения и приёмка |
| Человеческие часы ручной реализации | Не оценены; для выбранного способа исполнения не используются |
| Manus-кредиты | До контрольного этапа достоверно не оценены |
| API | Условный сценарий ниже; не измеренный прогноз |

Это означает: **первую реально работающую AWE разумно целиться получить в течение одного рабочего дня**, но пока нельзя гарантировать срок.

Риски: Router.Cheap, tool calling, Windows/WSL-связка, загрузка образов и поведение делегирования могут потребовать диагностики.

### Сценарий B — практическая AWE

**Agent Zero + один доказанно полезный готовый исполнитель.**

Например, OpenHands для coding-заданий. Остальные задачи остаются в Agent Zero. Не подключаем несколько фреймворков «на всякий случай».

**Новый код:** от нуля при наличии готового коннектора до одного или нескольких небольших адаптеров. Число строк до выбора контракта неизвестно; планировать тысячи строк сейчас необоснованно.

Критерии готовности: несколько типов миссий, передача задания внешнему исполнителю, получение результата и ошибок, отдельный review и успешный цикл исправления. Главный владелец миссии остаётся один.

| Измерение | Предварительный ориентир от начала проекта |
|---|---|
| Работа агента | 12–36 часов |
| Календарное окно | 2–5 рабочих дней |
| Участие человека | 2–6 часов |
| Человеческие часы ручной реализации | Не оценены и не используются как множитель |
| Manus-кредиты | Неизвестны до проверки реального адаптера |
| API | Условный сценарий ниже |

Этот диапазон менее надёжен, чем для сценария A: наличие API не доказывает простоту интеграции.

### Сценарий C — полная AWE GROUP

**Вся корпоративная архитектура с принудительными ограничениями и восстановлением.**

Продолжаем переиспользовать Agent Zero, интерфейс, инструменты и исполнителей. Разрабатываем только непокрытые сквозные требования.

**Новый код, агентное время, человеческие трудозатраты и кредиты сейчас достоверно неизвестны.** Предыдущие 240–480 часов не следует сохранять ни как срок работы ИИ, ни как подтверждённую смету этого сценария.

До оценки нужны результаты A и B, список фактических пробелов и точные требования к бюджету, правам, восстановлению и распространению приложения.

Критерии готовности здесь уже другие: технически обеспеченные ограничения, восстановление после сбоев, воспроизводимая приёмка, нагрузочные испытания и проверка дистрибутива.

## 6. Токены и стоимость — отдельно от времени и кредитов

Ниже — **арифметические сценарии**, а не предположение, что установка обязательно потребует указанное количество токенов.

Для сопоставимости использую ранее проверенные ставки Router.Cheap: Haiku 4.5 — $1/$5, Sonnet 4.6 — $3/$15, Opus 4.6 — $5/$25 за миллион входных/выходных токенов. При условном распределении токенов 60/30/10 средняя ставка составляет $2/$10. [Тарифы](https://router.cheap/pricing).

| Сценарий испытаний | Условный ввод / вывод | Стоимость при этой смеси |
|---|---:|---:|
| A: настройка и короткие проверки внутри AWE | 0,2–0,8 млн / 0,03–0,15 млн | $0,70–3,10 |
| B: проверки исполнителя и несколько миссий | 1–5 млн / 0,15–1 млн | $3,50–20 |
| Одна небольшая контрольная миссия | 0,1–0,5 млн / 0,02–0,1 млн | $0,40–2 |

Длинный контекст, исправления, vision, особенности тарификации и более дорогие модели могут существенно увеличить счёт.

**Это расходы Router.Cheap внутри AWE.** Они не включают кредиты Manus, оплату Codex, если он применяется, и другие сервисы. Токены Manus нельзя без подтверждённых правил пересчитать в его кредиты.

Фактически ожидаемые токены пока неизвестны. Для первого разрешённого этапа лучше согласовать небольшой денежный потолок, а не выдавать эти сценарии за точную смету.

## 7. Что выполнять параллельно

После запуска базовой системы можно независимо проверять модели, готовить инструкции разных профилей, проверять отдельные MCP-серверы и тестировать несвязанные инструменты.

Внутри миссии независимые исследования и проверки также могут выполняться параллельно, **если выбранная версия Agent Zero действительно поддерживает нужный режим и это подтверждено журналами**. Само делегирование не доказывает одновременное исполнение.

Нельзя без координации параллельно менять общий конфиг, обновлять одно окружение или редактировать одни файлы. QA итогового артефакта зависит от его появления. Несколько тяжёлых браузеров и сборок на вашем ноутбуке могут замедлить работу.

Параллельность уменьшает критический путь некоторых операций, но не автоматически уменьшает токены или кредиты.

## 8. Что должно быть готово после первого этапа

Без новых подсистем должны существовать:

1. Локально работающая Agent Zero, доступная через готовый интерфейс.
2. Проект AWE с файлами, инструкциями и штатной памятью.
3. Руководитель, исполнитель и Reviewer как профили.
4. Проверенные настройки минимум двух LLM-моделей.
5. Рабочие браузерные, файловые и терминальные действия.
6. Хотя бы одно реально используемое MCP-подключение.
7. Миссия с артефактом и отдельным проверочным заключением.
8. Сохранённая история и проверка штатного Backup/Restore.
9. Продолжение локальной работы после завершения участия Manus.

Не требуется собственная панель управления, новая БД, автоматический оптимизатор моделей или корпоративный QA-сервис.

**Даже для этой версии нельзя откладывать базовую безопасность:** ограниченное рабочее пространство, отсутствие ненужных прав, секреты вне Git и запрет опасных внешних действий. Разрешения инструментов Agent Zero не являются файловой песочницей — это прямо отмечено в документации профилей.

## 9. Контрольное задание для обоснованного пересчёта

Предлагаю после отдельного разрешения провести небольшую измеряемую миссию:

> Обработать небольшой CSV с заранее известными контрольными итогами, сохранить очищенный файл и отчёт, затем передать результаты отдельному Reviewer для независимой сверки.

Руководитель делегирует обработку одному профилю, проверку — другому. Используются две разные модели, локальные инструменты и подходящий готовый MCP-инструмент. Reviewer получает исходные данные и критерии, а не только текст исполнителя.

В дополнительной отрицательной проверке намеренно неверный результат должен быть отклонён. Это докажет наличие работающей проверки, а не формального сообщения «всё хорошо».

### Что измерять

| Метрика | Как получить |
|---|---|
| Календарное время | От запуска до проверенного результата |
| Участие человека | Отдельный учёт вмешательств |
| Делегирование | Профили, назначения и события в журнале |
| Использованные модели | Фактические model IDs, а не только настройки |
| Токены | Usage каждого запроса, включая QA и исправления |
| API-расход | Учёт отдельного ключа Router.Cheap |
| Manus-кредиты | Разница показаний до и после, если доступен точный учёт |
| Ошибки и переделки | Количество неудачных попыток и исправлений |
| Проверяемость | Совпадение с контрольными итогами и обнаружение дефекта |

Отдельно фиксируем **одноразовое развёртывание** и **повторное выполнение миссии**. Их нельзя смешивать: стоимость скачивания, настройки и диагностики не повторяется в каждом задании.

После успешного первого запуска желательно сделать ещё два сопоставимых прогона. Это даст диапазон времени и расходов, а не одно удачное наблюдение. Но CSV-миссия не оценит сложную интеграцию OpenHands: для сценария B понадобится отдельная короткая проба передачи coding-задания.

Пересчитывать весь проект нужно по **наблюдаемым типам работ и оставшимся пробелам**, а не умножением стоимости одного задания на произвольное количество этапов.

## Исправленный итог

**Первая AWE — это прежде всего развёртывание и конфигурация готового продукта, а не проект на 240–480 часов разработки.** Предварительный ориентир сценария A — один рабочий день при отсутствии блокеров, с нулём нового программного кода. Это цель планирования, пока не подтверждённая испытанием.

Сначала нужно доказать полный цикл «миссия → делегирование → несколько моделей и инструментов → действие → артефакт → отдельная проверка». Затем подключать готового внешнего исполнителя только при необходимости и развивать корпоративные функции по фактическим ограничениям.

**Сейчас выполнен только пересчёт и уточнение решения. Разработка, установка и испытания не начаты. Останавливаюсь до вашего отдельного разрешения.**
