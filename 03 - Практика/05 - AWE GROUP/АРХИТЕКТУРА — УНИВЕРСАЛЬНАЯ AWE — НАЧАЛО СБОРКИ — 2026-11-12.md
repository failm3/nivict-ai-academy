# AWE GROUP — универсальная система, а не агент под одну миссию

## Решающий запрос владельца (смысл исходных сообщений)

Владелец **повторно** потребовал перестать зацикливаться на CAREER-01 и тестировании отдельных локальных LLM. Требуется универсальная AWE GROUP: главные роли Head/Prompt Master, динамические многоуровневые подагенты, гибкий выбор облачной LLM и инструмента, доступ к локальному компьютеру и интернету, MCP, браузер, файлы, программирование, генерация, подключаемые плагины/Skills, дизайн, маркетинг, аналитика, автоматизации, долговременная память, контроль качества и обновляемость. Миссия CAREER-01 — **одна из** прикладных миссий, не определяет проектирование всей платформы. Пользователь устал от повторных диагностик и хочет начать разработку.

## Что уже имеется

- Подробный GitHub Canvas, пользовательская оргструктура: User → Prompt Master → explicit APPROVE → Head → динамический mission manager → рекурсивные специалисты → независимый QA → evidence/результат.
- 4504 **кандидата** инструментов и shortlist; не считать 4504 подключёнными/проверенными.
- Hermes Agent v0.22.2, Windows-native, на NIVICT-Workspace/runtime; его исполняемый CLI подтверждён; Git working tree clean; отдельная пустая тестовая директория.
- Docker Desktop v29.9.3, WSL2 Ubuntu, OpenCode, GitHub, PostgreSQL ранее был установлен; не менять прежние рабочие системы.
- Ollama установлена, но владелец **не хочет** её использовать до усиления железа. Исключить текущую локальную LLM из первых этапов.
- Agent Zero остаётся fallback, не надо устанавливать две платформы ради подготовительного цикла.

## Классы требуемых возможностей

1. Brain: LLM provider gateway и model routing с ограничениями стоимости и контекста, vision.
2. Execution: terminal/Code IDE/Git, files, browser, desktop computer-use, network/APIs, isolated Docker sandbox, artifacts.
3. Integrations: MCP server registry, Skills/plugins catalog с discovery, install/admission policy, on-demand tool choice.
4. Business capability packs: дизайн (Figma/UI/screenshot/visual QA), маркетинг (research/creative/campaign), аналитика (data, spreadsheets, reports), coding, documents, communication.
5. Organization: Prompt Master, Head, dynamic manager, recursive specialists, parallelism, independent QA/repair.
6. Governance: clear approvals for external actions, secrets vault, least privilege, spend caps, concurrency/depth, logging.
7. Continuity: durable tasks, files, memory, checkpoint/recovery, GitHub event records.

## Результат изучения официальных документов Hermes на 12.11.2026

Документы описывают много встроенных функций: terminal/files, browser/web, image_generate/vision, memory, cron, delegation, computer-use для Windows через cua-driver/MCP, MCP servers, installable/agent-created Skills, model_map и profile_routes в advanced-delegation, Docker backend и security approvals. Это означает, что **можно интегрировать имеющиеся возможности вместо разработки framework**.

## Что конкретно остаётся сделать, чтобы начать разработку

- Организовать отдельный репозиторий/ветку/рабочий каталог универсальной AWE, не нарушая установленный Hermes и существующую AWE.
- Подключить разрешённую облачную LLM через существующий Router.Cheap/OpenRouter/прямой provider с реально соблюдаемым денежным лимитом и безопасным хранением секретов; **не** Ollama.
- Создать единую конфигурацию/документацию компетенций и политики выбора инструмента, не устанавливая все 4504 кандидата.
- Настроить штатные file/shell/git/browser/web/MCP/GUI/vision/генерацию/Skill discovery, а затем интегрировать реальные design/marketing/analytics services по мере необходимости.
- Собрать один сквозной жизненный цикл mission/approval/head/dynamic delegation/QA/continuity и работающий интерфейс/точку входа.
- На каждую новую capability проводить **один необходимый интеграционный acceptance test**, а не отдельную серию искусственных тестов моделей.

## Что НЕ является блокером

- Нет необходимости иметь мощную локальную видеокарту, если используется cloud LLM.
- Нет необходимости сначала изучить/подключить все инструменты.
- Нет необходимости выбрать задачу CAREER-01 как единственную или первую функцию.
- Нет необходимости назначать Manus, Kortix и Codex параллельными руководителями: один локальный инженер-исполнитель OpenCode **или** Codex, независимый QA после результата.

## Контроль

Это запись решения о целях и требованиях. Сам агент не запущен, integrated toolchain и provider credentials не проверены в данном разговоре, оплачиваемые API вызовы не выполнены, существенные изменения файлов компьютера не выполнялись.
