# AWE GROUP — актуальная директива владельца (11 ноября 2026)

**Тип:** owner directive + operational handoff. **Приоритет:** P0. **Статус:** требование владельца зафиксировано; программное enforcement ещё не доказано.

## Обязательная цель, не менять

AWE GROUP — универсальная автономная мультиагентная система: миссия → Head → декомпозиция → специализированные исполнители → LLM и подходящие инструменты → параллельная работа → независимый QA → исправление → сохранение и продолжение. Первая прикладная миссия — CAREER-01. Исходный `/goal` зафиксирован отдельно в `E1-LIVE-AUTONOMOUS-LAUNCH-ORIGINAL-GOAL-2026-11-10.md`. Не заменять его собственной реконструкцией.

## Не обсуждать повторно — это уже принято владельцем

1. **Готовое прежде самописного.** До реализации очередного компонента проверить существующие встроенные возможности OpenCode/Hermes, каталог 4504 кандидатов, установленные инструменты, MCP/API/CLI, GitHub и проверенные библиотеки. Документировать поиск, альтернативы и обоснование, почему готовое не подошло. Не писать новый оркестратор/реестр/браузерный драйвер, если существующий пригоден.
2. **Каталог ≠ работающая интеграция.** 4504 — записи кандидатов, а не 4504 установленных инструмента. Имеющийся аудит: `02 - Аудит 4504 инструментов.md`; каталог: `04 - Инструменты/Каталог кандидатов/90 - Данные/catalog-all-4504.csv`. Не выдавать скрининг за функциональные тесты.
3. **Реальное приобретение возможности.** Минимальный сквозной контур: определить недостающую capability → поиск в существующем реестре → оценка происхождения/лицензии/совместимости/прав → изолированное подключение → smoke-test фактического вызова → зарегистрированный scoped adapter → применение агентом к настоящей задаче → независимый QA → сохранение повторно используемого Skill/рецепта. Если подключения нет, ставить BLOCKED, а не подменять красивой документацией.
4. **Производство важнее инфраструктурного самообслуживания.** Каждый инженерный шаг должен разблокировать конкретную пользовательскую способность и измеряемый результат CAREER-01. Не превращать миссию в бесконечный аудит/рефакторинг. OpenCode — рабочий исполнитель разработки, Hermes — уже присутствующий кандидат на универсальное выполнение (`awe/hermes_runtime`); не заменять стек и не вводить второй оркестратор до сравнительного теста на одинаковой задаче.
5. **Профессиональное портфолио.** Русский язык по умолчанию, предметная терминология продуктового дизайна и AI Agent Engineering, реальные кейсы и доказательства, адекватная информационная архитектура, исследование визуальных референсов, реальные скриншоты в браузере и независимая визуальная приёмка. Формальное прохождение DOM/HTTP-тестов не является приёмкой дизайна. Запрет выдумывать опыт, цифры, работодателей, коммерческие результаты.
6. **Модель выбирается по задаче.** Проверять фактическую доступность и лимиты; подбирать модель по компетенции/стоимости/качеству; независимый QA желательно другим семейством. Не считать наличие модели в списке доказательством реального доступа.
7. **Подтверждать факт, не обещать.** Worktree, `session_move`, assignment, PASS в отчёте ≠ созданный продукт, параллельное выполнение или автономность. Нужны сами артефакты, команды запуска, скриншоты, тестовые логи, git diff, независимый QA и сохранённый checkpoint.

## Ближайшая обязательная последовательность

**P0-A:** Инвентаризовать уже подключённые в OpenCode/Hermes/AWE реальные инструменты и 4504-каталог. Выбрать 1 браузерный инструмент с визуальными скриншотами и 1 интеграцию поиска/извлечения источников; проверить их реальные вызовы в WSL и оформить capability+Skill.
**P0-B:** На этой проверенной связке пересобрать один (!) профессиональный русскоязычный экран NIVICT, сверить с референсами, получить скриншоты desktop/mobile и независимую визуальную QA, исправить и предъявить владельцу. Не плодить ещё пять шаблонов.
**P0-C:** Продолжать CAREER-01 по существующим восьми утверждённым направлениям без потери исходных требований. Проверить пригодность 7 ночных вакансий, правдивость CV, происхождение проектов; внешние отклики и публикации — только после отдельного разрешения.
**P0-D:** Интегрировать уже проверенное в изолированном worktree исправление `FAILED`-зависимостей в AWE, провести регрессию; не объявлять исправление продакшен-готовым до merge/readback.
**P0-E:** Организовать автоматическую, проверяемую преемственность: оригинальное сообщение/артефакт → redact secrets → append-only GitHub archive → commit SHA → readback → видимый отчёт о сбое. Пока такой collector не протестирован, автоматическая синхронизация = NOT_IMPLEMENTED.

## Границы полномочий

- Не менять исходный `/goal`, не обходить существующие `UNKNOWN/HOLD`, лимиты, запреты на retry/платные вызовы; не создавать новые ключи/попытки для обхода HOLD.
- Не отправлять отклики, письма, сообщения и не публиковать сайты без явно отдельного разрешения. Не размещать секреты и персональные материалы в публичных репозиториях.
- Не отменять нужные QA/безопасность ради скорости; ограничить проверки теми, которые действительно доказуют способность. Не создавать второй источник истины о состоянии задач.
- **Оба используемых репозитория GitHub согласно API на 11.11.2026 публичные**, невзирая на старые тексты, утверждающие обратное. Не публиковать здесь токены, платёжные сведения, персональные документы или закрытые артефакты.

## Реальный статус, не подменять

- По архиву ночных worktree, переданному пользователем 11.11: есть 7 исследованных вакансий, два HTML-прототипа NIVICT, два черновика резюме, два близких карьерных viewer-проекта, инженерный патч планировщика и QA-материалы. Это **не** принятое профессиональное портфолио и **не** доказательство полностью автономной AWE.
- Визуальная QA NIVICT не была завершена; материалы отвергнуты владельцем как посредственные и англоязычные.
- Патч планировщика пока подтверждён в изолированной рабочей копии; интеграция в основную ветку не доказана.
- Локальные WSL/worktree изменения не тождественны опубликованному GitHub. Проверить git SHA и документы до выводов.
