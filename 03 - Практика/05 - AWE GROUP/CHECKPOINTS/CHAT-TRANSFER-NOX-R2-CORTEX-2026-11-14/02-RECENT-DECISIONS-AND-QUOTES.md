### Последовательность нынешней дискуссии

**01 — Зрелые агентные компании.** Пользователь: «Но теперь самое главное. Надо посмотреть, как это всё реализовано уже в работающих больших агентах ... как большие компании это всё реализуют». Исследовались публичные инженерные практики OpenAI Codex/Agents, Anthropic Claude Code/Agent SDK, Microsoft Agent Framework, Google ADK, Devin, Intercom Fin, Salesforce Agentforce и др. Вывод: использовать детерминированное исполнение, готовые Skills/Tools, verified QA, сохранение состояния, а не считать LLM всезнающим исполнителем.

**02 — Упущенные вопросы.** Пользователь: «Всё отлично. Как думаешь, что мы ещё с тобой не предусмотрели?» Ассистент сформулировал десять пробелов: калибровка компетенции, выбор типа исполнения, тесты реального обучения и его переноса, safe self-improvement с rollback, uncertain/stop policy, learning priorities, QA drift, экономика компетенций, shared verified experience, forgetting/revocation. Сформировались четыре контура Tool, Knowledge/Competence, Strategy, Meta.

**03 — Первоначальное большое ТЗ Cortex.** Пользователь попросил писать большое финальное ТЗ и сказал, что главное «...чтобы это всё быстро и чётко подключалось в Nox. Я категорически не приветствую разработку с нуля, если есть готовые плагины». Потребовал выяснить, может ли OpenCode реализовать и насколько легко интегрировать, а перед промптом проверять последнее состояние разработки. Исследование и initial final spec появились в чате.

**04 — Независимое мнение разработчика.** Пользователь: «...вот этот промпт сейчас отправить OpenCode, для того чтобы он проверил, насколько ... результат ... поможет ... улучшению ... самого Noxa ... и ... добавить свои пожелания». Потребовал положить большой текст в файл доступный OpenCode и потом Cortex, не вставляя весь в chat. Также добавил Cortex свободу в количестве суперагентов. Ассистент создал docs 01 и 02 на GitHub, commits f8be110... и 189851ff..., и поручил OpenCode docs-only independent review.

**05 — Будущий автономный инженерный режим.** Пользователь перед отдыхом: OpenCode должен не останавливаться на вопросах, иметь максимальную самостоятельность подключать и использовать полезные инструменты, сохранять checkpoint. Текущие prompt/checkpoint approvals на запись были docs-only. Ассистент подготовил черновик автономного инженерного промпта на будущее; разъяснил, что системные подтверждения прав и расходов нельзя отменить одним промптом.

**06 — Зафиксировать на будущее.** Пользователь: «Это тебе на будущее ... после ... аудита исследования Cortexa ... будем писать ... техническое задание ... самому OpenCode ... чтобы ты не забыл». Итог: Cortex исследует готовые решения → владелец утверждает → только потом OpenCode engineering R2.

**07 — Проверка прогресса.** Пользователь: «Проверь, пожалуйста, поалкод, на каком он ленде, как долго еще будет проводиться аудит». Последние observer записи показывали исходниковый audit, затем подготовку локальных 03/04/05 и контроль хешей. До публикации OpenCode честно отметил local-only status.

**08 — Проверка окончания.** Пользователь: «Можешь проверять, он закончил». OpenCode закончил docs review 04:41 МСК; создал локальные 03/04/05, но GitHub публикации тогда ещё не было.

**09 — Исправление недопонимания.** Пользователь уточнил: «Не-не-не-не. Не, он ещё ничего не занес ... давай напишем ему, чтобы он занёс». Ассистент подготовил узкую публикационную инструкцию без повторных исследований, без модификации Nox.

**10 — Маршрутизация моделей.** Пользователь показал скриншот глобальных replacement rules Router.Cheap. Было отмечено, что глобальная подмена GPT Sol на DeepSeek Flash и GPT Astra на Kimi может незаметно ухудшать инженерную точность и мешать диагностике. Это побочная тема; не входит в сам финальный промпт Cortex кроме необходимости не выдумывать model effectiveness.

**11 — Provider block.** Пользователь: «Он выдал политику безопасности провайдер заблокировал диалог для модели GPT. Тогда ладно, я ... GPT на Киме. Вот, напиши промт, чтобы он продолжил». Составлен короткий resume existing work prompt для Kimi K3.1 Pro. Не повторять завершённый audit, только публикация. Блокировка от провайдера не является разрешением обходить политику.

**12 — Support side-topic.** Пользователь спросил о прежнем обращении в поддержку. Gmail sent не подтвердил обращение по текущей ошибке. Затем пользователь сказал: «Не надо это. Проверь, что сейчас делают полный код». Не возвращаться к поддержке без нового запроса.

### Что ещё ранее определили, важно не потерять

- Исторический R1-Kortix enterprise research package в RESEARCH/KORTIX-2026-11-13-ENTERPRISE-RESEARCH был опубликован раньше, 23 документа, исследование, не runtime implementation; 173 requirements summary / 14 tickets — исторический scope, не заменяет текущий актуальный R2.
- Пользователь хочет, чтобы Nox обладал способностью находить не только инструменты, но и фундаментальные знания совершенно новых направлений, умел в них разобраться, выполнять реальную практику и закреплять verified skills. Он специально потребовал от ассистента самому обнаруживать недостающие архитектурные вопросы.
- Концептуальные профессиональные пакеты (UX/UI, engineering, marketing, management, research и открытые новые направления) должны включать sources, tools, Skills, workflows, real deliverables, quality oracles, а не только роли агентов.
- Пользователь хочет сохранить каждое важное сообщение/решение в GitHub/Obsidian, чтобы переходы между чатами не разрушали проектный контекст. Эту просьбу удовлетворяем подробной реконструкцией + точными ссылками на первичные документы; byte-by-byte всем сообщениям без export API гарантии нет.

### Три финальных обязательства для следующего ТЗ Cortex

**A. Полный target и минимальный R2 отдельно.** Не искусственно урезать open-world professional competence до статического web pilot.
**B. Проверенные готовые решения и скорость.** REUSE FIRST; exact package/versions/MCP/Skills/API/SDK/CLI/wiring; доказательная потребность в custom code; не застрять в бесконечной разработке.
**C. Свободное широкое исследование.** Разрешить использование большого числа superagents/моделей/поисковых направлений в фактических лимитах и существующих правах, без самовольного расширения полномочий, бюджета и production.
