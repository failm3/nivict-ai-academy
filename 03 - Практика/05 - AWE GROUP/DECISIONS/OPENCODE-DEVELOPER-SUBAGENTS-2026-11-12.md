# OpenCode — привлекать подагентов к разработке AWE GROUP

## Вопрос владельца

Будет ли Claude Opus 5.5, управляющий текущей сессией OpenCode Build, создавать других подагентов разработки? Следует ли разрешить ему это?

**Ответ:** OpenCode V2 поддерживает builtin `general` и `explore` subagents и настраиваемые project subagents, в том числе с индивидуальными cloud models и независимыми дочерними сессиями (foreground/background). По умолчанию `subagent` permission разрешён, если не указан последующий deny. Но возможность != факт использования. В полученном 04:36 ZIP экспорт сеансов `[]` и stats `subagents=0` относились к вероятно неправильной Windows-CLI/профилю. Это не подтверждает, что в реально запущенной WSL сессии дочерних агентов не было. Отчёт OpenCode v0.1 не упоминает разработческие child sessions, поэтому **использование не доказано**.

## Важно: исправление нашей конфигурации

В реально выгруженном `project-files/opencode.json`:

```json
"experimental": { "subagent_depth": 3 }
```

Текущие официальные документы OpenCode V2 определяют `subagent_depth` на **верхнем уровне**, а не внутри `experimental`. Требуется заменить прежнюю запись на:

```json
"subagent_depth": 3
```

Также при необходимости явно разрешить launch `{ "action":"subagent", "resource":"*", "effect":"allow" }` внутри `permissions` после других правил. Точно проверить действующую версию `opencode` перед применением.

Документация: https://opencode.ai/docs/config ; https://opencode.ai/docs/agents ; https://opencode.ai/docs/tools .

## Принцип организации разработки

- Claude Opus 5.5 Build — один технически ответственный lead, работает в текущем clean-room.
- Делегировать независимо подготовленные блоки параллельно дочерним агентам: например, MCP/browser, persistence, QA/security, UI — после устранения P0, с назначенными cloud models только при проверенной Router.Cheap маршрутизации.
- Для каждой ветви отдельные файлы/области владения; один ответственный интегрирует и запускает тесты.
- Independent reviewer read-only; не считать Claude «сам себя проверил» независимым QA.
- Избегать гонок при записи в те же файлы, бесконтрольных рекурсивных spawn и общего shell/host доступа.
- Не вводить новых расходов-approvals на каждый запрос: владелец разрешил тратить существующий prepaid Router.Cheap баланс, но запретил автоматические пополнения.
- Не переносить старые NIVICT/AWE проекты в clean-room.
- Логи child session IDs, agent IDs, модели, задачи, Git diff и артефакты должны фиксироваться для доказательства.
- В отличие от разработческих подагентов OpenCode, реализуемое дерево subagents **внутри AWE** остаётся отдельной функцией продукта, не доказанной отчётом v0.1.

## Действия

Не перезапускать разработку. Передать ведущему OpenCode короткое уточнение на проверку и включение подагентов при следующем логическом пункте. Никаких изменений локальных файлов со стороны ChatGPT здесь не выполнено.
