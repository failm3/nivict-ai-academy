# AWE GROUP — обязательное решение владельца: fresh clean-room implementation

Владелец прекратил предыдущую стратегию чтения/ремонта старых реализаций. Прямая воля: **новое пустое рабочее пространство и новый код с нуля по одному самодостаточному мастер-промпту**, содержащему ранее согласованные требования. **Новый инженерный агент не должен читать исходники, историю, Canvas, промпты, логи, архивы, test fixtures или конфиги из старых AWE/NIVICT проектов; не должен пытаться чинить старый код.**

Это не означает отказ от использования открытых сторонних библиотек и готовых agent-engine runtime как зависимостей: допускается использование и адаптация сторонних mature open-source технологий, но не импорт старого пользовательского проекта. Hermes Agent в старом NIVICT-Workspace/runtime не модифицировать; если он выбран в качестве зависимости — использовать независимую чистую копию.

Цель разработки: **универсальная AWE GROUP**, не CAREER-01. Архитектура: User → Prompt Master → explicit APPROVE → Head → динамически созданный manager → рекурсивно создаваемые специализированные агенты → QA → durable results. Все необходимые capabilities: local computer shell/files/git/browser/GUI, internet/APIs, MCP tool discovery, Skills/plugins, coding/design/marketing/analytics/generation/docs, cloud-only model routing, memory/checkpoints, spend caps, approvals, QA, continual evolution.

OpenCode — **инженерный инструмент разработки**, не конечная AWE. Старт с нового пустого каталога под WSL; отдельные настройки/ключи по возможности. Ни Codex, ни Manus, ни Kortix не назначаются дополнительными руководителями для этого clean-room проекта. Безопасность: выполнять низкорисковые действия в отдельном workspace, любые обращения к чужим личным файлам, внешним аккаунтам, установка неизвестного ПО, платежи и публикации — с подтверждением. Закрытые учетные данные не помещать в git. Ollama не использовать на этом этапе. Не выдавать оболочку/промпты за готового автономного агента без реальной демонстрации.

Старый репозиторий `failm3/nivict-ai-academy` здесь использован **только как архив решения для непрерывности беседы**. Его **не передавать в новом проекте как источник** и не поручать читать.

Проверка существующей модели OpenCode 2026: `https://opencode.ai/docs/permissions/` — V2 default external_directory allow, настройка проекта и хоста обязательна для реальной изоляции. В новой конфигурации запретить external_directory, требовать approve для shell, deny root/sudo/deletion/credentials. Промпт сам по себе не OS sandbox.

Действующая стадия: решение сформулировано, новый проект на ПК пользователя ещё не создан, Router.Cheap ключи не изменены, платные API не вызывались.
