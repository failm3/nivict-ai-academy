# Непрерывный журнал и задачи для OpenCode во время разработки

«Он там уже что-то сделал, да, пока он делает, также отправьте задачу, я скинул весь журнал его работы. Вот.»

## Доказательства

Последний реально загруженный сюда архив текущего clean-room: `AWE-OpenCode-Audit-20261112-043624.zip` (12 ноября, 04:36 МСК). Он уже проанализирован: примерно 623 структурируемых события, 17 project files, реальный TypeScript scaffold, но 0 экспортированных sessions из-за вероятно неверного CLI. **Новых логов после заявленного запуска 3 параллельных подагентов и 1 независимого ревьюера пользователь не прикрепил.** Нельзя уверенно перечислить реально использованные модели, child session IDs и токены.

## Задача OpenCode от владельца (для передачи вручную в живую TUI, не для автоматического запуска через GitHub)

Продолжай текущий roadmap и текущие 3 development subagents + reviewer, не останавливай, не переписывай с нуля. Настрой continuous evidence в новом clean-room проекте:

1. Фиксируй каждую задачу и её owner/subagent role, `session_id`, `parent_session_id`, точный `provider/model`, время запуска/завершения и итог.
2. Для каждого фактического tool call сохраняй tool name, time, success/fail, exit code, файлы/артефакты, но не секреты, payload auth или личные данные.
3. Сохраняй воспроизводимые проверки: команда, код возврата, результат, путь к output/evidence, независимое QA/review; не называй LLM score доказательством интеграционной приёмки.
4. Собирай usage/cost если провайдер реально сообщает; отличай measured от estimated, не выдумывай цену и вызовы.
5. Веди Git checkpoints на значимых результатах после проверки secret leaks и `.gitignore`; сохраняй diff/status и readback.
6. Дай короткий фактологический snapshot текущей команды: реальные модели и child session IDs, активные работы и их статус; если невозможно измерить — явно скажи.
7. Приоритет P0 безопасности/approval и затем динамические, рекурсивные, мультимодельные агенты/Tools; не отвлекай исполнителей на пространные отчёты.
8. Только новый clean-room, не читать старые AWE/NIVICT. Не отключать текущую разработку или расходовать вне pre-paid Router.Cheap; no auto top-up.

Публиковать журнал в отдельном GitHub archive допустимо только после исключения токенов и чувствительной информации; **новый код** остаётся в clean-room проекте, без загрузки в старый репозиторий.

## Способ передачи

Ассистент в этой беседе **не имеет прямого канала к локальной TUI OpenCode пользователя**; нельзя выдавать запись в GitHub за команду, фактически доставленную OpenCode. Дать владельцу одно сообщение для вставки в OpenCode и проверить факт исполнения по новой выгрузке.
