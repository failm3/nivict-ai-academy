## Что именно собрать (реальный код, не только проект)

### A. Unified Registry
- Настоящий исполняемый importer для всех **4504 исходных record IDs** Cortex; без потерь, с проверкой числа, схемы и SHA входа, с сохранением source/provenance и отображением дублей на общий upstream при наличии доказательств.
- Никаких утверждений, что 4504 — работающие инструменты: все изначально `UNVETTED`. Поддержи виды `mcp_server`, `api`, `agent_skill`, `script_cli`, `knowledge_source`, `workflow`, `agent_recipe`, `verifier`, `reference_or_service`; неизвестные типы не притворяются callable.
- Версия/digest, лицензия, interfaces (входы/выходы), platform/deps, permissions/effects, trust/status, qualification receipt, compatibility, last verified; отсутствующее = `UNKNOWN`.
- Раздельная БД/namespace/feature flag, не модифицирующие рабочие данные Nox. Повторный импорт должен быть идемпотентным. Без автоматического скачивания/исполнения кода.

### B. Librarian — детерминированный поиск без обязательной LLM
- Рабочий локальный FTS (возможно гибридный поиск только если есть измеримое улучшение); keyword + aliases + types + capabilities + permissions/trust/effects + platform; ранжирование, top-k, rationale, NOT_FOUND.
- Progressive disclosure: Head получает только короткие метаданные кандидатов, не весь каталог и не тысячи schemas.
- Удобный typed TypeScript SDK и CLI/API: `searchCapabilities(requirement, filters)`, `getCapability(id)`, `getCompatibility(id, hostProfile)`, `listQualificationState(id)`; названия можешь изменить с объяснением.
- Возврат читаемых доказательств и uncertainty; никаких исполняющих прав у Librarian.

### C. Integration adapter для существующего Nox
- Минимальный TypeScript контракт `Head -> Librarian -> existing Capability Plane -> existing executor -> existing QA`.
- Используй существующие tool registry, grants/approval, sandbox, recovery, logs и SDK; покажи конкретные extension points и минимальный diff plan. Не делай неиспытанную правку в реальном working tree.
- Feature flag по умолчанию OFF, безопасный rollback/uninstall без миграции/потери core state.
- Модуль должен быть пригоден к загрузке в Node/TypeScript Nox без создания нового основного сервиса или Python daemon, если без него нет конкретно доказанной необходимости.
- Библиотека знаний и реестр инструментов — связанные, но раздельные объекты; проверяемые competence/lesson records с provenance/ACL, без ложных обещаний обучаемости.

### D. Reuse-first / безопасность
- Проведи краткую предметную reuse-matrix: какую существующую реализацию Nox/SDK переиспользовать, что нужно адаптировать, что отсутствует; откажись от дублирования.
- Все внешние описания, манифесты, search results и найденные Skills считать untrusted data. Не использовать их как управляющие инструкции или новые полномочия.
- Qualification/admission — на стороне Nox: DISCOVERED -> INSPECTED -> QUALIFIED -> SCOPE_APPROVED -> ACTIVE -> REVOKED/QUARANTINED. Смена digest/schema/rights отзывает qualification.
- Учитывать лицензии, provenance, scope/ACL ДО выдачи данных в prompt. Не переносить private data между миссиями. NO secrets in source, outputs, logs.
- Детерминированные операции выполнять скриптами без LLM: import, dedup, FTS, hash, schema, contract checks.

### E. Verified Agent Blueprints — повторное использование успешных специалистов

**Дополнительное прямое решение владельца (2026-11-15):** Nox должен запоминать хорошо проявивших себя специализированных агентов и находить их для похожих миссий, не создавая всю специализацию заново.

- **Не сохранять и не запускать «живого агента» как бессрочный процесс.** Сохранять версионированный **Agent Blueprint / Agent Recipe** — декларативный рецепт восстановления нового экземпляра существующим механизмом динамических специалистов Nox: роль, назначение, шаблон инструкций, необходимые capabilities/Skills, предполагаемый маршрут/модель (под host-owned policy), входные/выходные контракты, применимость, ограничения, зависимости и ожидаемые критерии успеха. Никакой новой фабрики агентов, второго Head или agent runtime.
- **Promotion только после доказанного результата:** blueprint может иметь статус `CANDIDATE`, `VERIFIED_FOR_SCOPE`, `DEPRECATED` или `REVOKED`. Перевод в verified допускается на основе независимой приёмки конкретной миссии/артефактов с immutable provenance, а не самопохвалы LLM или одного текста «агент справился». Не обещать универсальность за пределами проверенного scope.
- **Сохранение:** компактная запись и ссылки на evidence (ID, SHA, версия, acceptance, источник, проверенная применимость, ошибки/exclusions), но **без** токенов, credentials, приватных материалов, полного контекста пользователя, скрытых chain-of-thought, runtime leases или чужих ACL-данных. Сохранять только разрешённые обезличенные либо правильно scope-bound данные. По отзывам доступов/компетенций должна действовать инвалидизация.
- **Поиск и повторное применение:** Librarian при похожей миссии ищет blueprint через тот же FTS/фильтры, оценивает applicability, версии и доступные права, затем предлагает Head `reuse / adapt / build_new`. Head создаёт **новый экземпляр** специалиста через текущий Nox, повторно применяя проверенные настройки, но заново запрашивает фактически необходимые scoped grants; библиотека сама не исполняет агента.
- **Не подменять обучение:** reuse blueprint ≠ fine-tuning модели и ≠ доказанный перенос компетенции. Отдельный fresh-task тест сравнит подходящий сохранённый blueprint с генерацией нового специалиста; фиксировать качество, затраты и неудачи. `NO_BENEFIT` допустим.
- **Минимальная реализация в рамках этой сборки:** typed schema, сохранение/поиск/загрузка рецепта, отбор только verified-for-scope, примитивная проверка совместимости и один воспроизводимый mock/fixture roundtrip `mission accepted -> blueprint saved -> similar mission -> fresh specialist reconstructed -> QA`. При отсутствии доступа к текущему исходному Nox — adapter-contract fixture и статус `INTEGRATION_PENDING_LIVE_SOURCE`.
- **Стоп-правило:** не строить marketplace агентов, self-training pipeline, глобальный recommender, граф компетенций или систему постоянных запущенных агентов; достаточно доказанной возможности безопасно повторно использовать квалифицированный рецепт.

## Реальные демонстрации и независимые тесты

Обязательны воспроизводимые команды запуска и машиночитаемые результаты:
1. Fresh install/build/typecheck на чистом окружении без Router.Cheap; importer: **4504/4504** исходных IDs, сохраняются source records, дубли не потеряны; повторный import без мутаций/роста числа.
2. Offline search с независимыми test queries нескольких разных категорий; search, фильтры, NOT_FOUND, evidence, стабильная выдача, zero paid LLM calls для обычного lookup.
3. Adversarial fixture: поддельный MCP, prompt injection в описании, неизвестная лицензия, подмена digest, отсутствие grants — fail closed, никакого выполнения/эскалации.
4. Реальный end-to-end в изолированном mock/fixture host: Head-подобный caller находит previously unknown candidate, проверяет контракт и отдаёт его **существующему** (в тесте mock) admission/QA через адаптер; результат и trace сохраняются.
5. Если предоставлен read-only/current-source доступ к Nox, выполни контрактную проверку на конкретной ревизии и укажи hash. Без такого доступа честный `INTEGRATION_PENDING_LIVE_SOURCE` и runnable instructions, а НЕ ложное `LIVE_INTEGRATED`.
6. Независимый QA должен воспроизвести результаты, проверить integrity и перечислить FAIL/UNKNOWN. Никакого GREEN без логов и артефактов.
7. Verified Agent Blueprint: после подтверждённого QA сохранить рецепт специалиста, повторно найти на похожей новой задаче, создать свежий экземпляр через existing Nox-style adapter, отдельно проверить права/совместимость/QA. Negative controls: unverified/revoked/private blueprint не должен возвращаться или выполняться; тест не должен создавать новую agent factory.

### Суть продукта, которую Cortex должен понять

AWE GROUP / Nox — не магазин плагинов, не надстройка над единственным LLM и не набор профессиональных workflow. Целевой продукт — **автономный цифровой исполнитель**, которому владелец ставит ранее неизвестную разрешённую миссию. Nox понимает результат и границы, строит план, собирает динамическую команду, выбирает между скриптом/API/одним агентом/командой, находит недостающую компетенцию, через свой действующий Capability Plane проверяет и получает разрешение на использование, исполняет реальную работу, перестраивается при ошибке, предъявляет независимые доказательства результата и сохраняет проверенный опыт. При похожей миссии Nox умеет находить **Verified Agent Blueprints** и создавать нового специалиста по уже проверенному рецепту — с новыми актуальными grants, а не с прежними секретами. Массовое количество подключений не является целью; целью является **общее повторно применимое умение осваивать требуемые возможности**, не меняя ядро под каждую профессию.

Ключевые существующие узлы (по независимому аудиту): Prompt Master (typed specification/approval), Head (mission-specific roles/plans), Mission Manager (parallel/recursive delegations, leases/checkpoints/recovery), файлы/shell/web tools, существующий Playwright MCP path с известными ограничениями, LibSQL persistence, host-owned routing/ledger, deterministic QA gate + LLM reviewer, artifact integrity. Не путать это с полностью подтверждённой универсальностью, полноценным general MCP/Skills installer или доказанным transferable learning.

**Библиотека Cortex — узкий переносимый модуль для этого ядра:** единый индекс capabilities и источников, локальный Librarian с дешёвым детерминированным поиском, typed adapter к действующим разрешениям/исполнителям/QA Nox; отдельно — verified Agent Blueprints. На интеграции источники вроде Cortex-4504 и новых внешних находок остаются кандидатами, а не автоматически установленным executable code.
