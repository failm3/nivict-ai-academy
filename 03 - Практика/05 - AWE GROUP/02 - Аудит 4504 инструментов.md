## Как должен выглядеть мастер промптов, даже если переиспользуем Spec Kit

`Исходный запрос → LLM-черновик с provenance → программная JSON Schema проверка → независимая семантическая проверка требований → PASS / FAIL / UNCLEAR → (коррекция или согласование с пользователем) → версия ТЗ → головной агент`.

Требования помечать `USER / PROJECT / INFERRED / UNKNOWN`. Нельзя выдуманные условия автоматически считать утверждёнными. Согласие двух LLM не доказывает верность; нужны источники и измеряемые проверки.

## Тест перед архитектурным решением

Одно одинаковое задание на копии «Сайт Жив»: пользовательский запрос → уточнение критических требований → изолированная проектная линия → выбор JS-скрипта/LLM/инструмента → реальный QA → checkpoint/resume → отчёт. Сравнить Agno, Microsoft Agent Framework и существующее NIVICT ядро.

Критерии: доля реально выполненных требований, пропущенные требования, стабильность возобновления, минимальные права, фактическая стоимость моделей, логирование/наблюдаемость, скорость, объём интеграции, лицензия, обслуживаемость.
