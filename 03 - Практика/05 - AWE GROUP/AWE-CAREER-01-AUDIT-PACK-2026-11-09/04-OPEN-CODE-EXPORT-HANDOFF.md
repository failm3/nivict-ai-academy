# 04 · OpenCode — безопасная сборка снимка AWE для пяти аудиторов

> **Операционное задание на экспорт, НЕ архитектурный аудит, НЕ требование реализовывать или исправлять код.** Само создание этого документа **не означает, что экспорт выполнен**. Он предназначен для исполнения в локальной WSL Ubuntu владельца с доступом к действительному проекту.

## Цель

Создать **один неизменяемый, верифицируемый baseline** текущей AWE GROUP для дальнейшей передачи **пяти независимым аудиторам**. Все пять должны видеть одинаковую версию кода и те же сырые свидетельства, не теряя незакоммиченные изменения. Одновременно подготовить **безопасную для передачи очищенную копию**, не размещая в публичном GitHub исходники/журналы с секретами.

Документация миссии уже находится в:
`https://github.com/failm3/nivict-ai-academy/blob/main/03%20-%20%D0%9F%D1%80%D0%B0%D0%BA%D1%82%D0%B8%D0%BA%D0%B0/05%20-%20AWE%20GROUP/AWE-CAREER-01-AUDIT-PACK-2026-11-09/README.md`

## Абсолютные ограничения

1. **Read-only по отношению к исходным проектам**: не делать `git add/commit/reset/clean/checkout/merge/pull/push`, не форматировать, не изменять файлы исходного дерева, не менять DB schema/данные, не запускать сервисы/миграции/исправления тестов. Изменения допускаются **только в новом каталоге экспорта**.
2. **Не запускать саму AWE, агентные миссии, новые тесты с побочными эффектами, job applications, публикации или платные внешние API.** Вызовы LLM, необходимые самой сессии OpenCode, — единственное исключение; не обращаться к сторонним внешним сервисам в рамках экспорта.
3. **Никаких секретов в сообщениях модели, stdout, отчётах или GitHub.** Не выводить значения `AWE_ROUTERCHEAP_KEY`, `OPENAI_API_KEY` и других env/token/key; не читать/печатать содержимое приватных `.env`, ключей, browser profiles, credentials, session cookies. Если нужна оценка чувствительности — использовать локальное автоматическое сканирование с выводом только имён файлов, типов находок и счётчиков, без совпавших значений.
4. Не использовать `/tmp` как основное место сборки (ранее `/tmp` был заполнен). Использовать каталог в домашней директории на диске с достаточным местом.
5. Не скачивать внешние зависимости. При нехватке программ/места обозначить `BLOCKED` и указать конкретную причину.
6. **Не загружать автоматически ZIP/TAR в GitHub, чат, облако, провайдеру LLM или внешнее хранилище.** Места хранения пакета выбираются отдельно владельцем.
7. **Сохранять различие** между реальным сегодняшним runtime, прежним E0, отчётом Astra, наблюдением LEVEL 2 и артефактами продукта Vacancy Radar.

## Порядок работы

### A. Инвентаризация и freeze состояния

- Зафиксировать дату с часовым поясом, ОС/WSL, Node, Python, PostgreSQL version (без чтения БД), OpenCode version, `uname`, версию `package.json`, текущие ветку/HEAD и сведения `git status --porcelain=v1 -uall` / `git diff --stat` / `git diff --name-status` (без содержимого секретных файлов).
- Выполнить предварительную оценку доступного места и объёма исходников/логов, включая скрытые и ignored файлы.
- Снять **список обычных файлов** (включая незакоммиченные и untracked), отдельно список ignored/generated/cache/secret-candidates. Не следовать по символьным ссылкам за границы исходных каталогов.
- Не предполагать, что 828 строк предыдущего `git status` описывают сегодняшнее состояние.

### B. Локальная первичная сохранность (только в защищённом каталоге)

- Создать `/home/nox/awe-audit-handoff-2026-11-09/` (или другую свободную домашнюю директорию) с правами `0700`.
- Внутри сделать `private-baseline/`: сохранение всех необходимых файлов runtime, незакоммиченного кода, конфигураций без потери содержания, документации и сырых свидетельств для владельца. **Никакой автоматической публикации**.
- Файлы с секретами, БД/сырые дампы, cookies, tokens, провайдерные credentials и иные опасные материалы **не копировать в распределяемую часть**; при необходимости сохранить **локально, отдельно и с ограниченным доступом**, не предъявляя их OpenCode/LLM текстом. Если экспорт даже локально небезопасен — отметить исключение и причину.
- Кэши и `node_modules` можно исключить из передаваемой копии, **но перечислить в inventory**, сохранить lockfiles и воспроизводимые инструкции. Пропущенные ignored-файлы, которые реально нужны запуску, нельзя молча потерять.
- Исходный `.git` не копировать как потенциально чувствительный blob; вместо этого фиксировать refs, статус, метаданные и **присутствующие рабочие байты файлов**. При необходимости приватно хранить git bundle/commit tree отдельно после проверки секретов.

### C. Внешние свидетельства, не смешивая источники

В `evidence/` скопировать при доступности:
- `/home/nox/awe-level2-observation/`: `logs`, `snapshots`, `copy`, `indep` с сохранением исходной структуры и указанием полного происхождения.
- Артефакт `E1/live/runs/<mission_id>/vacancy-radar/` и другие уже существующие результаты миссий, не переписывая их.
- Существующие тестовые логи, миграции, fixtures и отчёты, относящиеся к E0/E1/LEVEL 2, с метками источника, даты и степени доверия.
- При доступности `02-inventory.md`, `verify-inputs.mjs`, `career-crash-fixture.mjs` из **старого** Astra-аудита.
- Любые недоступные каталоги отметить в `MISSING-INPUTS.md`, не создавать заглушки и не утверждать наличие.
- Постоянные live DB и реальные аккаунты **не трогать**; если для доказательств понадобится DB snapshot, запросить отдельное разрешение, предложив обезличенный read-only экспорт, но **в рамках этой задачи не выполнять**.

### D. Отдельный пакет для пяти аудиторов

- Создать `auditor-bundle/` — копию из допустимых файлов; **не использовать очевидные `.env`/keys/tokens/DB files/private account logs**.
- Сделать предварительное автоматизированное обнаружение возможных секретов, учётных URL, PII и приватных переписок. Не выводить сырые совпадения в LLM; сохранить только локальный отчёт с классификацией и путями. Сканер **не гарантирует** отсутствие чувствительного содержимого.
- Сырые журналы, содержимое которых невозможно безопасно проверить, **не включать в распределяемый архив**: записать `REQUIRES_MANUAL_REVIEW`, сообщить владельцу. Не заменять документы выдуманным `REDACTED_OK`.
- Сформировать `INPUTS.md`, `MANIFEST.sha256` по файлам, `TREE.txt`, `EXCLUSIONS.md`, `MISSING-INPUTS.md`, `GIT-STATE.md`, `ENVIRONMENT.md`, `SENSITIVE-REVIEW.md`, `INTEGRITY-CHECK.md`.
- Архивировать `auditor-bundle/` в ZIP или TAR.ZST, проверить целостность распаковки, записать SHA-256 архива, размер, количество файлов, список реально импортированных источников.
- **Не делать архив частью публичной Academy**. Не передавать его автоматически в эту беседу. Сначала нужен контроль владельца, затем одинаковый архив аудиторам.

### E. Контроль неизменности оригинала

- Сравнить `git status --porcelain=v1 -uall` до и после, проверить хеши выбранных контрольных файлов runtime и документации.
- Если в процессе исходный runtime всё-таки изменялся другими процессами, **не маскировать race**, отметить snapshot consistency как `UNVERIFIED`, указать расхождение. Если источник меняется прямо во время экспорта, сначала создать отдельный стабильный снимок без остановки/изменения оригинала, затем работать с ним.
- Не использовать формулу «отсутствие git diff = все байты идентичны» для untracked/ignored. Фиксировать отдельную верификацию этих групп.

## Ожидаемый итог

В одном кратком отчёте сообщить:
1. **Откуда именно** взят актуальный runtime: путь, ветка, commit, наличие uncommitted/untracked, состояние consistency.
2. **Что собрано**: структура каталога, две области (private / auditor), число файлов, общий размер, manifest, SHA-256 архива.
3. **Что исключено/не найдено**: код, логи, игнорируемые и чувствительные материалы, отсутствующие evidence.
4. **Результат контроля**: `PASS`, `PARTIAL` или `BLOCKED` и причины.
5. **Какие действия остались владельцу** перед выдачей всем пяти аудиторам: чувствительные файлы, права/хранилище, недостающий snapshot.
6. Подтверждение: исходный код, DB, Git и внешние сервисы **не были изменены** (или точное описание расхождения).

**Стоп после экспорта и проверки.** Не начинать аудит, рефакторинг или исправление ошибок по собственной инициативе.
