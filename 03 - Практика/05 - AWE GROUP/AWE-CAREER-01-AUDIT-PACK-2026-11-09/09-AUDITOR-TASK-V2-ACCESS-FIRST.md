## Фаза 0 — обязательная проверка доступа. НЕ ПРОПУСКАТЬ.

До любых архитектурных рекомендаций:

- Определи доступные тебе инструменты для чтения веб-страниц, бинарных вложений, работы с файлами и запуска локального кода. Нельзя заявлять, что инструмент существует, если его нет.
- Получи **байты** ZIP, а не только GitHub-страницу с его названием. При наличии файловых инструментов проверь размер, SHA-256, целостность архива и список файлов.
- Продемонстрируй чтение содержимого как минимум трёх **реальных исходных файлов** из разных подсистем, например из `AWE-RUNTIME/awe/`, `AWE-RUNTIME/E1/` и `AWE-RUNTIME/tests/`, указав точные пути и факты, найденные в содержимом. НЕ описывай файлы по их названиям.
- Подтверди, что можешь читать полную спецификацию восьми блоков CAREER-01, а не один README.
- Если нет возможности скачать ZIP через веб, попробуй использовать фактически прикреплённое к разговору вложение. **Веб-страница GitHub с ZIP не считается доступом к исходникам.**
- Если среда не умеет читать ZIP даже из вложения, сообщи в одном коротком сообщении `INPUT_BLOCKED`, конкретную техническую причину и попроси **текстовую версию исходников (TXT/MD), распакованные файлы или среду с файловым исполнением**. Не составляй предварительный «полный аудит» и не трать время на обширное исследование внешних фреймворков, пока исходники недоступны.
- Если доступны только отдельные документы, явно разделяй документальный обзор и аудит кода. Не выдавай документальный обзор за технический аудит.

**Требуемый первый ответ при успешной фазе 0:** `INPUT_READY`, имя/размер/SHA-256 (или честное `NOT_VERIFIED`), число файлов и три конкретных исходника с фактами из их содержимого. После этого продолжай исследование автономно, не ожидая отдельного одобрения. При ошибке — только `INPUT_BLOCKED` с причиной.

Изучи требования из `01-OWNER-REQUIREMENTS.md` полностью. Внимание: решения владельца из 9 ноября уточняют историческую редакцию 7 ноября. Разбей реальную AWE на подсистемы и установи на основе файлов и тестов:
