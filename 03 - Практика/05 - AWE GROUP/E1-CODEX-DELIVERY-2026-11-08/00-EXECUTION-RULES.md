## Контракты и архитектурные запреты
- **Один** координатор AWE (D03) и **одна** граница учёта/reserve/settle (D09), общие MissionSpec, Capability, Task, EffectIntent, ArtifactRef, QAResult; career/product имеют только разные адаптеры. Не создавать альтернативный scheduler/ledger для отдельных миссий.
- План LLM — **предложение**, проверяемое кодом: typed DAG, capabilities, права, бюджет, срок, class данных, origin. Модель/бот/скрипт не получает прямой DB write, private credentials или необследованную сеть.
- QA технически независим: отдельная роль/ключ, замороженный digest проверяемого объекта, failure injection, объективный readback. Автор кода не вправе сам подтвердить внешнее действие.
- Прежние `AUTO01_MOCK_ONLY` и `LOOPBACK_MOCK` не снимать с исторических профилей; создать явный `AWE_E1` composition/entry.
- Разрешения на отдельные внешние действия, PII, бюджеты, регионы, платные API, публикацию, новую БД и release — **ограниченный мандат владельца**. Рутинные шаги в уже выданном мандате не требуют повторного одобрения. В среде Codex могут дополнительно действовать её собственные разрешения.
- Не запускать исторический PG E0 и не трогать его PGDATA; новые схемы и тесты — только новый namespace/DB.
- Не выдавать synthetic/mock/fixture за live. Не утверждать exactly-once у внешнего сервиса без его идемпотентности или надёжного readback: в неизвестном исходе `HOLD/OUTCOME_UNKNOWN`, не повторять blindly.
- Секреты и личные документы — только в отдельном разрешённом vault/локальном хранилище, не в Academy, PR, логах или тексте задач. Проверить сервисные условия для HH/API.

## Порядок внутри каждого задания
1. **Discover:** обнаружить фактические реализации и контракты, перечислить reuse/changes, сообщить только существенные блокеры.
2. **Implement:** узкий vertical slice, test-first для риска, небольшие законченные diff; изолированная ветка source и явный build/version manifest.
3. **Verify:** позитивный сценарий + негативные проверки, в том числе crash/restart/ACL/unknown, всё что применимо.
4. **Publish:** commit + PR только в согласованный приватный source-репозиторий и согласованную ветку. Academy обновлять результатами, ссылками и состояниями, а не дублировать секретные runtime-артефакты. Без самовольного merge/deploy.
5. **Report:** `IMPLEMENTED / TESTED_OFFLINE / VERIFIED_LIVE / PARTIAL / BLOCKED`, какие команды выполнялись, идентификаторы и SHA-256, что осталось неизвестным, что получает следующий исполнитель.
