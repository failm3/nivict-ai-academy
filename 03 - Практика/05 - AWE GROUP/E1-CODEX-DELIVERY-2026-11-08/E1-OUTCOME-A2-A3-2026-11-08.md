## Coding Executor и открытые границы

Подготовлен grant-bound executor: patch proposal → изолированный Git worktree/ветка → фиксированные тесты → независимый QA → draft intent. Реальные временные Git red→green и отдельный decimal holdout отклонили формально проходивший плохой patch. Его model/accounting/OS sandbox/publisher fixtures — явно doubles. **Настоящая GitHub-задача, кодовый fix и PR от AWE не выполнены**; текущий source PR подготовил интегратор. [Отчёт](https://github.com/failm3/awe-group-runtime/blob/09f1a864e6fa26afa62ffac3249c6532a6116175/E1/CODING-EXECUTOR-REPORT.md).

В G1/G2/G3 подтверждены только перечисленные bounded local behaviors; full E1/Pilot не принят. Global cross-project GPU admission, hostile OS isolation, production human AuthN/vault, 24 h soak, disaster recovery и широкий benchmark не доказаны. G4/G5/G6 — NOT_RUN. Платные/облачные API, реальные отклики, публикация сайтов, auto merge и production не запускались.

Параллельно готовы OS sandbox/fixed runner + patch capability binding; global resource admission/recovery/soak preparation; независимый adversarial QA Coding Executor. Для первого фактического self-development теста требуется конкретный разрешённый GitHub issue и owner grant с base SHA/точными путями/лимитами; protected core, auto merge и release остаются запрещены. Новых дизайнерских проектов не предлагается.
