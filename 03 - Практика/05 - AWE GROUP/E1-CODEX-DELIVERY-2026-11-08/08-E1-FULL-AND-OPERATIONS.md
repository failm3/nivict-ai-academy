# B5/C2 · Полная CAREER-01, портфолио и автономная эксплуатация
**Статус:** READY_FOR_CODEX AFTER PILOT. **Разрешено параллельно:** аудит материалов, исследования, продуктовый brief и контрактные/тестовые fixtures до пилота.

## Цель
Из ограниченного пилота вывести полезную, надёжную AWE-CAREER-01 на том же ядре: проверяемые кейсы, реальные продукты по утверждённым требованиям владельца, две версии CV, ограниченная серия разрешённых откликов, мониторинг, восстановление и проверенное обучение навыкам. Не путать карьерные результаты с доказательством универсальности по неизвестным классам.

## B5 — карьерная кампания
- Поддержать разные разрешённые источники с ограничениями выдачи, обновлением cursors и явным отчётом охвата `source+window+filters`. У каждой релевантной вакансии outcome: sent/readback, queued, rejected with reason, blocked, unknown.
- Готовить индивидуальный пакет с factual provenance, дедупликацией, QC, актуальными версиями CV и валидными ссылками. Первый mail-channel — только один из адаптеров; добавление HH/ATS/browser требует подтверждённой операции и нового capability approval.
- В рамках заранее утверждённого кампанийного MissionGrant самостоятельно отправлять серии до max_count/expiry/budget, без ручного согласования каждой штатной заявки. Ускорение не оправдывает дубли и обход прав площадки.
- Monitor/reconcile по источникам; новое приглашение — отдельный owner alert, дальнейшую переписку ведёт владелец. Не выдавать `SENT` за `VIEWED` или `HIRED`.

## B5 — портфолио по требованиям владельца
- Сверить текущие публичные URL, исходники, commit/build, роль владельца и разрешённые факты. Не подменять работающий продукт красивой картинкой или выдуманными метриками.
- По **утверждённым briefs** обеспечить проектирование → дизайн/состояния → frontend/backend → интеграционный browser QA → независимый UX review → исправления → разрешённую публикацию и readback. **Не формировать от лица владельца новые дизайнерские идеи без его задания.**
- Приёмка каждого проекта: реальная доступная функция, исправный API/хранение где нужно, responsive 320/390/768/1440, клавиатура/labels/focus, ошибки/empty/loading, доступность, performance измерено, визуальная оценка reviewer; ноль критических дефектов и подтверждённые права.
- Маркировать provenance `HUMAN_OR_CODEX_ASSISTED` vs `AWE_EXECUTED`. Для второго нужна трасса mission → workers → QA, а не только общий Git commit.

## C2 — непрерывность и развитие
- **24 часа в staging/ограниченной кампании** с независимым измерением состояния, как минимум один controlled restart central, отказ одного worker, временная недоступность upstream, тест restore на отдельной копии с отключённым egress. Отдельно проверять восстановление DB+object manifests и reconciliation after backup.
- Нулевые потерянные принятые результаты, нулевые повторные внешние эффекты, нулевые отрицательные бюджеты; восстановление измерять, время записывать, а не обещать.
- Отделить project memory от shared registry; fact/reason/source/TTL, запрет cross-project leakage. Обучение: новая технология → проверенная практическая операция → независимый тест → versioned skill registry. Fine-tuning и обучение весов не выдавать за память.
- Безопасный updater: issue → isolated source branch → fail-before/pass-after → независимый QA → PR → staging/canary → rollback. Worker не подписывает себе новые права и не переписывает защищённое ядро без принятой release policy.
- Backups и multi-node расширять по фактическим рискам. Второй ПК и Hermes/Agno — возможности, не обязательная зависимость первого результата.

## Gate E1 Full
1. Приняты оба pilot класса A/B с разными domain manifests и одинаковым core.
2. Есть подтверждённые версии CV и реальные работающие portfolio URLs с QA и правами.
3. Серия минимум двух различных разрешённых подач с provider ID/readback, tracked pool, прозрачные blockers.
4. Монитор/уведомления и 24-часовой наблюдаемый цикл, failure recovery, persisted usage/cost.
5. Неподтверждённое не маркировать `VERIFIED_LIVE`. При задержке внешнего доступа продолжать локальные зависимости и честно фиксировать блокер.

## Выход
Отдельные source PR/release, portfolio reviews по фактическим владельческим briefs, live receipts без персональных данных, coverage registry, 24-hour run report, restore exercise, skill/updater audit. GitHub Academy — только индексы, статусы, версии и доступные без секретов доказательства.
