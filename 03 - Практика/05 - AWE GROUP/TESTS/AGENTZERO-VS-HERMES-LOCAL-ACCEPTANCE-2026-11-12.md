# AWE GROUP — сравнение Agent Zero vs Hermes на локальном компьютере

**Цель:** выбрать один готовый local-first runtime для собственной AWE GROUP, а не строить новый framework и не оплачивать работу чужих облачных agent platforms. Это **тестовый протокол**, а не разрешение выполнять команды, расходовать токены или менять инфраструктуру.

## Кто исполняет

- Владелец: approvals, бюджеты, выбор основного движка.
- ChatGPT: протокол, разбор фактических логов, независимое сравнение и отчёт.
- **Один** локальный исполнитель: OpenCode **или** Codex, но не оба одновременно; владельцем сообщалось, что OpenCode уже установлен в WSL2.
- Manus: optional внешняя экспертиза только после появления доказательств и при согласованном расходе кредитов.
- Kortix: не задействовать на этапе local-first теста.

Не предоставлять внешним платформам ключи и удалённый доступ без отдельного согласования.

## Безопасность и этапы

**P0 / ТОЛЬКО ДИАГНОСТИКА:** из PowerShell прочитать `wsl -l -v`, `docker --version`, `docker info`, в Ubuntu `command -v docker; command -v hermes; command -v opencode; free -h; df -h ~`. Никаких модификаций, sudo, скачиваний, смены ключей, изменений конфигов AWE и OpenCode.

**P1 / УСТАНОВКА ТОЛЬКО ПО APPROVE:** после review диагностики — изолированное окружение Agent Zero (официальный Launcher + контейнерный runtime, persistent workspace, UI только localhost, без Host access) и отдельное окружение Hermes (не менять existing `~/.hermes`/старую AWE без инвентаризации). Не использовать `curl|bash` или `irm|iex` без предварительного просмотра/контроля содержания скрипта. Не ставить два heavyweight runtime в один shared workspace. При любых конфликтах STOP.

**P2 / МОДЕЛИ ТОЛЬКО ПО APPROVE:** одинаковый provider/model set, инструменты, бюджет. Для локального Ollama 4B возможен стартовый smoke-test, но если model tool calling/specific format не поддерживает, это не доказывает дефект фреймворка. Для серьёзного сопоставления возможен строго ограниченный existing Router.Cheap key; владелец выбирает и подтверждает максимальную реальную сумму. Сам лимит в prompt не является hard cap — при отсутствии технического ограничения тест не запускать платно. Секреты/учётные данные не публиковать в repo/logs. Отдельные измеряемые бюджетные ключи предпочтительны, если разрешено.

**P3 / ИДЕНТИЧНЫЙ ТЕСТ (ПОСЛЕДОВАТЕЛЬНО):**

Предоставить каждой платформе одну фиксированную approved миссию:

> «Сформируй один ограниченный, но полный и датированный MARKET-срез CAREER-01 для разрешённого источника вакансий. Prompt Master уточняет/фиксирует требования и ждёт явного approve владельца. После approve Head проверяет доступный бюджет и инструменты и создаёт менеджера миссии. Менеджер создаёт временных подагентов для получения данных, нормализации/дедупликации и независимой проверки; при необходимости один подагент делегирует дальше. Вся работа только read-only, без входа в аккаунты, отправки откликов, сообщений и публикаций. Верни CSV/JSON, coverage log, evidence direct links, QA verdict и сохранённое состояние с проверяемыми файлами.»

У обеих платформ одинаковы объём входа, источник, период, модели, права и критерии приемки. Ограничить одновременно работающие подагенты (например, 2) и максимальную вложенность (например, 2 уровня ниже Head), а не бесконечный spawn.

**P4 / ПРИЁМКА:**

- Prompt Master действительно не запускает опасное действие до APPROVE.
- Head делегирует специализированному manager, тот создаёт/назначает работников; отдельная вложенная ветвь доказана логами, не только описана в чате.
- Две согласованные модельные роли используются фактически, видно model ID/endpoint/usage.
- Реальный инструмент читает вакансию/источник, сохраняет ссылку, требования, доступность/дату проверки; найденные дубли не попадают в принятый реестр.
- Independent QA использует исходники и артефакт, умеет отклонить специально внесённый дубликат/ошибку классификации.
- Артефакт сохранён, перезапуск интерфейса не уничтожает состояние, нет ложного утверждения о гарантированном crash recovery.
- Есть наблюдаемые wall time, active user time, tokens, true API cost, faults/retries, trace.
- Никаких запрещённых внешних actions, доступов к host beyond sandbox, или нарушений бюджета.

Вопрос об автоматическом возобновлении неизвестных внешних действий отдельный, более строгий тест будущей полной AWE; отсутствие этой функции не заменять ложным «PASS».
