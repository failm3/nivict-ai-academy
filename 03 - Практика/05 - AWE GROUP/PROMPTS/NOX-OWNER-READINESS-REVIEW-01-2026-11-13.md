# NOX-OWNER-READINESS-REVIEW-01 — независимая оценка готовности Nox к работе без OpenCode

**Дата подготовки:** 2026-11-13. **Статус:** DRAFT / READY TO SEND / **NOT SENT TO OPENCODE**.
**Исполнение, изменение кода, установка, платные API и стресс-тест НЕ разрешены этим документом.**
**Контекст:** Nox — основное имя создаваемого автономного агента AWE GROUP. OpenCode — инженерный исполнитель, не обязательная часть пользовательского пути.

## Задание для OpenCode

Ты — ведущий инженер OpenCode, разработавший текущий runtime AWE GROUP / Nox.

Владелец планирует передать Nox в непосредственное самостоятельное пользование, без OpenCode как обязательного посредника.

**Пока не изменяй код, не запускай платные испытания и не расширяй инфраструктуру.** Проведи независимый критический анализ реального текущего runtime, локальных изменений, предыдущих миссий, трасс и тестов.

### Ответь на вопросы

1. **Что объективно мешает сегодня передать Nox владельцу?** Перечисли пять наиболее критичных блокеров, с доказательствами из кода и логов. Отличай неработающий механизм от непроверенного.
2. **Почему Tool Intelligence не обеспечивает полноценное самостоятельное использование инструментов?** Проверь обнаружение, выбор, адаптеры MCP/API/CLI, выдачу прав, подключение, вызовы дочерними агентами и регистрацию результатов. Что именно уже существует, а что только декларируется?
3. **Может ли Nox самостоятельно подключать новые инструменты?** Предложи минимальную безопасную архитектуру такого подключения, повторно используя существующий код и реестр, без создания второго оркестратора.
4. **Насколько автономны Prompt Master, Head, Agent Factory, Mission Manager, Model Router, Memory и QA?** Для каждого укажи REAL / PARTIAL / NOT_IMPLEMENTED / NOT_VERIFIED и предъяви подтверждение.
5. **Какие реальные сбои наиболее вероятны при одновременном выполнении нескольких миссий?** Особое внимание: lost context, checkpoint, race conditions, tool grants, timeouts, модельные маршруты, бюджеты и восстановление.
6. **Какой большой стресс-тест способен проверить Nox объективно?** Подготовь воспроизводимый план контрактных, интеграционных, нагрузочных, аварийных и end-to-end испытаний. Отдели бесплатные локальные тесты от платных API-запусков, рассчитай предельные расходы.
7. **Что является минимальным состоянием готовности к передаче владельцу?** Предложи измеримые критерии, необходимые тесты и порядок исправлений. Укажи, какие компоненты можно отложить без ущерба для самостоятельной работы.
8. **Оспорь собственную рекомендацию.** Есть ли более простой способ добиться самостоятельной эксплуатации, чем продолжать развивать существующую архитектуру? Сравни минимум две альтернативы.

- Не выполняй merge, deployment, установку новых пакетов или платные вызовы.
